# ai-coach

Личный ИИ-тренер на данных Garmin. **Статус: в работе** (холд 2026-10-03, снят 2026-10-06), архитектура утверждена, следующий шаг — кабан-кволити и спайк Garmin.

## Требования
- Тесная интеграция с Garmin: сон, HRV, Body Battery, стресс, readiness, активности, вес.
- Цели гибкие, сочетаются и меняются: гибрид (сила+выносливость), триатлон, похудение, набор массы. Нужны приоритеты, фазы и история смены целей.
- Рекомендации с учётом целей и фактического выполнения (план vs факт).
- Анализ прошлого и динамики, разбор ошибок в питании/сне/тренировках.
- Тренер сам отправляет тренировки на часы.
- Интерфейс: терминал (CLI/TUI), веб — опционально позже.

## Ответы пользователя
- Подписки Garmin Connect+ нет.
- Питание сейчас не ведёт, готов вводить в приложение.
- Тренировки — автоматически на часы.
- Цели гибкие.

## Решения
- Язык: Python (2026-10-06) — ближе к Garmin-библиотекам (python-garminconnect).
- Ответы на груминг свинопаса (2026-10-06):
  - MVP: синк, профиль целей, план/факт, утренний readiness в CLI.
  - Часы: Garmin Forerunner 970. Вес — ручной ввод.
  - Тренировки отправляются на часы только после «ок» в CLI. Силовая на часах нужна в MVP.
  - Конфликт целей решает пользователь. Смену фазы предлагает тренер, пользователь подтверждает.
  - LLM: подписка Claude (через Claude Code), не API.
  - Запуск вручную, без cron/сервера.
  - Если авторизация Garmin сломалась — ручной импорт.
  - Питание: свободный текст, точность КБЖУ не критична.

## Черновой скелет (не утверждён)
1. Синк: python-garminconnect (≥0.3) → локальный SQLite (кэш истории).
2. Ядро: профиль целей с историей, план, журнал план/факт, лог питания (свободный текст → LLM → КБЖУ), модель нагрузки (CTL/ATL, прогрессия весов).
3. Агент: Claude с tools — утренний readiness, недельный разбор, перепланирование.
4. Интерфейс: CLI/TUI + отправка workouts на Garmin.

## Разработка
- Установка: `uv sync` (Python 3.12+); для `make smells` нужен Qlty CLI (`curl -fsSL https://qlty.sh | sh`).
- Все проверки: `make check` — ruff (линт+формат), pyright (strict для src/), qlty smells (сложность, дубли), vulture (мёртвый код), pytest с покрытием ≥94%.
- Тренер: `make install-trener` кладёт symlink `~/.local/bin/тренер`; команда `тренер` запускает `claude --agent coach` в проекте.
- Мутации: `make mutate [MOD="ai_coach.load.*"]` — фоном, по умолчанию изменённые модули; отчёт в `reports/mutmut.txt`, повторная сводка — `make mutate-report`.

## Вес и еда
- `coach weight 82.4` — записать вес; `coach food "борщ 300 г, хлеб 40 г"` — записать еду текстом, у каждого продукта граммы (без них /coach-food спросит). Время — местное «сейчас», LLM в Python нет, пишется только в базу. Видно в `get_morning_snapshot` (weights, food_today).
- КБЖУ считает скилл `/coach-food` через MCP (`get_food_pending`, `save_food_nutrition`); записи с КБЖУ он не меняет.

## Тренировка на телефон (без часов)
- Страница-плеер: https://papahusserl.github.io/ai-coach/ (папка `player/`, публикуется GitHub Actions `pages.yml`). Тренировка целиком в ссылке после `#` (`v1.` + сжатый JSON), сервера и базы нет, данные на сервер не уходят.
- Ссылку отдают MCP-инструмент `get_workout_link(workout_id, time?)` — поля и картинка с QR-кодом — и команда `coach link <id> [--time HH:MM]`. Адрес плеера — `$AI_COACH_PLAYER_URL` или `PLAYER_URL` в `workouts/phone.py`. Ссылка длиннее 2000 символов — ошибка: сократить заметки или разделить тренировку.
- На телефон: отсканировать QR камерой или открыть тот же чат в мобильном Claude. На странице — шаги, «Старт» (таймер, звук, вибрация, экран не гаснет), «В календарь» (.ics), «QR этой страницы».
- Claude Desktop: в `claude_desktop_config.json` → `mcpServers.ai-coach` с той же командой, что и для `claude mcp add` ниже.
- Ограничения: на iPhone нет вибрации, в беззвучном режиме нет звука; без GPS шаги по метрам закрываются кнопкой «Готово».
- Локально: `python -m http.server` из `player/`, тесты плеера — `make player-test` (входит в `make check`, нужен Node.js).

## Нагрузка вне тренировок
- `coach sync` после Garmin читает календарь macOS (EventKit), `~/.claude/todo.json` и `~/bin/hb-watch/{done,pending}` (только чтение) и кладёт в базу события календаря и счётчики (туду открыто/закрыто, груминг сделано/ждёт); названия задач и имён файлов в базу не попадают. Ошибка календаря не мешает остальному и Garmin.
- Конфиг вне репо: `~/.config/ai-coach/workload.toml` (или `$AI_COACH_WORKLOAD_CONFIG`): `[calendar] work/personal/hobby/rest/ignore = [названия календарей]`, `[paths] todo, hb_watch`. Нет конфига — календарь пропускается, туду и груминг читаются по умолчанию. Календарь, которого нет в разметке, считается `unknown` (в нагрузку не входит), его имя печатает sync.
- Доступ к календарю: macOS спросит разрешение у терминала, из которого запускается `coach sync` (`тренер`). После смены терминала или обновления macOS разрешение может «протухнуть» — включить заново: Системные настройки -> Конфиденциальность и безопасность -> Календари. Нужен macOS 14+ и `uv sync` (ставит pyobjc-framework-EventKit, на других системах календарь недоступен).
- MCP: `get_workload(date_from, date_to, events=false)` — часы встреч по категориям и после 19:00, выходные, счётчики; названия событий только при `events=true` на один день. В сводке тренера — `workload` (7 дней назад) и `workload_ahead` (7 дней вперёд, без названий).
- Вечерний чек-ин: `тренер вечер` (скилл `coach-evening`) или `coach feel <1-5> ["текст"] --mood <1-5> --stress <1-5> --work <ч> --hobby <ч> --rest <ч>`: настроение, стресс и часы работы/хобби/отдыха за сегодня (часы перезаписываются). Низкое настроение (<= 2) и высокий стресс (>= 4) попадают в отклонения.
- Общая нагрузка и перегруз: `get_overload(date)` — `total` (одно число из тренировок, работы, хобби, вечеров/выходных, туду и груминга; ручные часы главнее календарных) и сигналы `total_streak`, `evening_streak`, `weekend_work`, `recovery_drop`, `todo_growth`. Веса и пороги — константы в `load/overload.py` (стартовые, пересматриваются по 2-3 неделям данных), формула — в `docs/architecture-2026-10-06.md`. В сводке: `overload`, `evening_done_today`, `workload_ahead[].overloaded`.
- Недельный обзор: `get_weekly_review(weeks=4)` (1-12) — ISO-недели Пн-Вс от старой к новой, последняя неполная (`partial`): TSS, общая нагрузка, часы работы/вечера/выходных, туду, средние mood/stress/сон/readiness и `delta` к предыдущей неделе; выводов в коде нет. В сводке `week_review_due` — в воскресенье (текущая неделя) и понедельник (прошедшая), пока нет записи; тренер проводит обзор по `.claude/agents/coach-week.md` и отмечает его `coach review done [--week <понедельник>] ["заметка"]` (по умолчанию: в понедельник — прошедшая неделя, иначе текущая; до 04:00 — как у `coach feel`; повтор заменяет запись).
- Роль тренера собрана из файлов: ядро `.claude/agents/coach.md` (до 15 КБ) и подгружаемые по требованию `coach-wellbeing.md` (нагрузка, выгорание), `coach-nutrition.md` (спортпит, добавки, витамины, кладовая и рецепты), `coach-week.md` (недельный обзор), `coach-onboarding.md` (профиль); вечерний чек-ин — скилл `coach-evening`.

## MCP и скиллы тренера (Claude Code)
- MCP-сервер (stdio) читает агрегаты из базы (без raw_json); списки отдаются как `{rows, truncated}`, до 60 строк и 20 000 символов, у рядов по датам остаются самые новые строки. Пишет только черновики: `create_draft_workout`, `cancel_draft_workout` (только draft -> cancelled), `propose_phase`. Инструментов отправки на часы и удаления нет, в Garmin сервер не ходит: утверждает и отправляет пользователь (`coach approve`, `coach push`).
- Регистрация (один раз; путь к репо свой):
  `claude mcp add ai-coach -- uv run --project /путь/к/ai-coach python -m ai_coach.mcp_server`
  База — `$AI_COACH_DB` или `~/.local/share/ai-coach/coach.db`.
- Нагрузка (CTL/ATL): пульс покоя берётся из ответа сна в базе (последний день с данными, не старше 14 дней, иначе ошибка «сделай coach sync»). Пороговый пульс (LTHR) свой для каждого вида (бег/вело/плавание), таблица `thresholds` с историей: `coach sync` забирает беговой порог (endpoint `latestLactateThreshold`, source `garmin_lt`) и пороги видов из пульсовых зон Garmin (`get_heart_rate_zones`, source `garmin_zones`). Чего Garmin не дал, считается на лету (source `derived`): беговой минус смещение (вело −7, плавание −12, константы в `load/thresholds.py`), а без бегового порога — 0.89 × максимальный пульс из активностей. Силовая — 35 TSS/час, растяжка — 0, незнакомый вид — по беговому порогу. `get_load` отдаёт `thresholds` ({вид: {lthr, source, date}}), снапшот — тоже. Нет данных — в снапшоте `load_error`, остальное работает.
- Скиллы лежат в `.claude/skills/` и подхватываются в этом репозитории: `/coach-morning` (утренний разбор и рекомендации по восстановлению, Sonnet), `/coach-plan` (план недели черновиками, Sonnet; форматы тренировок в `.claude/skills/coach-plan/spec-formats.md`), `/coach-food` (раз в день считает КБЖУ записей еды без него, Sonnet). Поле `model` во frontmatter и имена инструментов `mcp__ai-coach__*` в `allowed-tools` на живом Claude Code не проверены.
