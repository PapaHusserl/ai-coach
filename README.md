# ai-coach

Личный ИИ-тренер на данных Garmin. **Статус: в работе** (холд 2026-10-03, снят 2026-10-06), архитектура утверждена, следующий шаг — кабан-кволити и спайк Garmin.

## Требования
- Тесная интеграция с Garmin: сон, HRV, Body Battery, стресс, readiness, активности, вес.
- Цели гибкие, сочетаются и меняются: гибрид (сила+выносливость), триатлон, похудение, набор массы. Нужны приоритеты, фазы и история смены целей.
- Рекомендации с учётом целей и фактического выполнения (план vs факт).
- Анализ прошлого и динамики, разбор ошибок в питании/сне/тренировках.
- Тренер сам отправляет тренировки на часы.
- Интерфейс: терминал (CLI/TUI), веб — опционально позже.

## Ответы пользователя
- Подписки Garmin Connect+ нет.
- Питание сейчас не ведёт, готов вводить в приложение.
- Тренировки — автоматически на часы.
- Цели гибкие.

## Решения
- Язык: Python (2026-10-06) — ближе к Garmin-библиотекам (python-garminconnect).
- Ответы на груминг свинопаса (2026-10-06):
  - MVP: синк, профиль целей, план/факт, утренний readiness в CLI.
  - Часы: Garmin Forerunner 970. Вес — ручной ввод.
  - Тренировки отправляются на часы только после «ок» в CLI. Силовая на часах нужна в MVP.
  - Конфликт целей решает пользователь. Смену фазы предлагает тренер, пользователь подтверждает.
  - LLM: подписка Claude (через Claude Code), не API.
  - Запуск вручную, без cron/сервера.
  - Если авторизация Garmin сломалась — ручной импорт.
  - Питание: свободный текст, точность КБЖУ не критична.

## Черновой скелет (не утверждён)
1. Синк: python-garminconnect (≥0.3) → локальный SQLite (кэш истории).
2. Ядро: профиль целей с историей, план, журнал план/факт, лог питания (свободный текст → LLM → КБЖУ), модель нагрузки (CTL/ATL, прогрессия весов).
3. Агент: Claude с tools — утренний readiness, недельный разбор, перепланирование.
4. Интерфейс: CLI/TUI + отправка workouts на Garmin.

## Разработка
- Установка: `uv sync` (Python 3.12+); для `make smells` нужен Qlty CLI (`curl -fsSL https://qlty.sh | sh`).
- Все проверки: `make check` — ruff (линт+формат), pyright (strict для src/), qlty smells (сложность, дубли), vulture (мёртвый код), pytest с покрытием ≥94%.
- Тренер: `make install-trener` кладёт symlink `~/.local/bin/тренер`; команда `тренер` запускает `claude --agent coach` в проекте.
- Мутации: `make mutate [MOD="ai_coach.load.*"]` — фоном, по умолчанию изменённые модули; отчёт в `reports/mutmut.txt`, повторная сводка — `make mutate-report`.

## Вес и еда
- `coach weight <кг>` — записать вес; `coach food "борщ 300 г, хлеб 40 г"` — записать еду текстом, у каждого продукта граммы (без них /coach-food спросит). Время — местное «сейчас», LLM в Python нет, пишется только в базу. Видно в `get_morning_snapshot` (weights, food_today).
- КБЖУ считает скилл `/coach-food` через MCP (`get_food_pending`, `save_food_nutrition`); записи с КБЖУ он не меняет. Группы продуктов (`groups`) обязательны при записи КБЖУ; старым записям их дописывает `save_food_groups`. После обновления кода перезапусти `тренер`: MCP не перечитывает код при `/clear`.

## Тренировка на телефон (без часов)
- Страница-плеер: https://papahusserl.github.io/ai-coach/ (папка `player/`, публикуется GitHub Actions `pages.yml`). Тренировка целиком в ссылке после `#` (`v1.` + сжатый JSON), сервера и базы нет, данные на сервер не уходят.
- Ссылку отдают MCP-инструмент `get_workout_link(workout_id, time?)` — поля и картинка с QR-кодом — и команда `coach link <id> [--time HH:MM]`. Адрес плеера — `$AI_COACH_PLAYER_URL` или `PLAYER_URL` в `workouts/phone.py`. Ссылка длиннее 2000 символов — ошибка: сократить заметки или разделить тренировку.
- На телефон: отсканировать QR камерой или открыть тот же чат в мобильном Claude. На странице — шаги, «Старт» (таймер, звук, вибрация, экран не гаснет), «В календарь» (.ics), «QR этой страницы».
- Claude Desktop: в `claude_desktop_config.json` → `mcpServers.ai-coach` с той же командой, что и для `claude mcp add` ниже.
- Ограничения: на iPhone нет вибрации, в беззвучном режиме нет звука; без GPS шаги по метрам закрываются кнопкой «Готово».
- Локально: `python -m http.server` из `player/`, тесты плеера — `make player-test` (входит в `make check`, нужен Node.js).

## Нагрузка вне тренировок
- `coach sync` после Garmin читает календарь macOS (EventKit), `~/.claude/todo.json` и `~/bin/hb-watch/{done,pending}` (только чтение) и кладёт в базу события календаря и счётчики (туду открыто/закрыто, груминг сделано/ждёт); названия задач и имён файлов в базу не попадают (кроме названий событий тренера, записанных в календарь после «да»). Ошибка календаря не мешает остальному и Garmin.
- Конфиг вне репо: `~/.config/ai-coach/workload.toml` (или `$AI_COACH_WORKLOAD_CONFIG`): `[calendar] work/personal/hobby/rest/ignore = [названия календарей]`, `[calendar.demand] challenge = [regex на заголовок]` (рабочая встреча с совпадением — вызов, остальные — помеха), `[paths] todo, hb_watch`. Нет конфига — календарь пропускается, туду и груминг читаются по умолчанию. Календарь, которого нет в разметке, считается `unknown` (в нагрузку не входит), его имя печатает sync.
- Доступ к календарю: macOS спросит разрешение у терминала, из которого запускается `coach sync` (`тренер`). После смены терминала или обновления macOS разрешение может «протухнуть» — включить заново: Системные настройки -> Конфиденциальность и безопасность -> Календари. Нужен macOS 14+ и `uv sync` (ставит pyobjc-framework-EventKit, на других системах календарь недоступен).
- Экранное время (необязательно): [ActivityWatch](https://activitywatch.net) на Mac (aw-server на `127.0.0.1:5600`, оконный вотчер и afk-вотчер) — второй источник часов работы и хобби. `coach sync` и `coach screen [--days N]` (по умолчанию 1 день, нужна для вечернего чек-ина) читают из aw-server только агрегаты по категориям за день 04:00→04:00 и вечер 19:00→04:00 и кладут в базу `screen_work_hours`, `screen_hobby_hours`, `screen_browser_hours`, `screen_evening_hours` (`source='screen'`) и, если размечены вызов/помеха, `screen_challenge_hours`, `screen_hindrance_hours` (части работы). Часы работы и хобби в нагрузке: ручные (`coach feel --work/--hobby`) > экран > календарь; день без событий окон счётчиков не получает. Нет секции `[screen]` — экран пропускается (`coach screen` — одна строка и код 1), AW не отвечает — ошибка в итоге sync, остальное пишется.
- Claude Code: `coach sync` и `coach claude [--days N]` (по умолчанию 1 день; первый раз `--days 29`) читают локальные транскрипты `~/.claude/projects` (путь — `[paths] claude_projects`) и кладут в базу по дням `claude_prompts`, `claude_prompts_evening`, `claude_decisions`, `claude_repos`, `claude_switches` (`source='claude'`) и короткие имена проектов у `claude_repos`; текстов реплик нет, сессии тренера и субагенты не считаются, в нагрузку числа не входят. Транскрипты Claude Code хранит 30 дней. В MCP — поля `get_workload`, имена проектов только при `events=true` на один день, в сводке — ключ `claude`.
- Разметка экрана — в `workload.toml`, вне репо: `[screen] url = "http://127.0.0.1:5600"` (по умолчанию), `work`/`hobby`/`browser`/`meeting = [имена приложений]` (регистр `meeting` важен: aw-server сравнивает имена точно; окна приложений созвонов считаются и во время afk), `[screen.title.<приложение>] work`/`hobby = [regex на заголовок окна]` (регистр не важен, hobby побеждает; кавычки в regex нельзя). `challenge`/`hindrance = [имена приложений]` — вызов и помеха внутри работы (подмножество `work`/`meeting`/приложений с `[screen.title]`; в обоих списках нельзя). Obsidian — в `work`. Приватность: названия приложений и заголовков окон остаются в конфиге и в aw-server; в базу, ответы MCP и репо идут только часы по категориям (работа, хобби, браузер, вечер и, если размечены, вызов и помехи).
- MCP: `get_workload(date_from, date_to, events=false)` — часы встреч по категориям и после 19:00, выходные, счётчики, часы экрана `screen_*` (в т. ч. `screen_challenge_hours`, `screen_hindrance_hours` — вызов и помехи внутри экранной работы), `challenge_hours`, `hindrance_hours` (части `work_hours` календаря); названия событий и их `demand` (вызов/помеха) только при `events=true` на один день. В сводке тренера — `workload` (7 дней назад) и `workload_ahead` (7 дней вперёд, без названий).
- Вечерний чек-ин: `тренер вечер` (скилл `coach-evening`) или `coach feel <1-5> ["текст"] --mood <1-5> --stress <1-5> --work <ч> --hobby <ч> --rest <ч> [--thoughts <1-5>] [--flow|--no-flow] [--hindrance <1-5>] [--valuable <1-5>]`: настроение, стресс, часы работы/хобби/отдыха за сегодня (часы перезаписываются), мысли о работе вечером, погружение, помехи и ценность дня; в конце чек-ина тренер спрашивает, что осталось и с чего начать завтра (в базу не пишет, записать в туду — самому). Новые поля тренер только собирает (`get_wellbeing`), на них не реагирует. Низкое настроение (<= 2) и высокий стресс (>= 4) попадают в отклонения.
- Дневная оценка: `coach focus <фокус> <усталость> <усилие> ["текст"]` (три цифры 1–5: фокус, умственная усталость, «трудно заставить себя»; до 04:00 — вчера), просмотр `coach log focus [--date D]`, MCP `get_focus_log(date_from, date_to)`. Тренер только собирает оценки, не реагирует на них; в сессии `тренер` фраза «фокус 4 2 3» выполняет ту же команду.
- Срыв в момент: `coach slip "текст как есть" [--at HH:MM]` (свободный текст эмоций, без оценок; до 04:00 — вчера), просмотр `coach log slip [--date D]`, MCP `get_slip_log(date_from, date_to)` с `awake_h` и `stress_garmin` (средний стресс Garmin ±15 мин вокруг отметки, `null` — нет замеров; данные до последнего `coach sync`). Текст уходит в Claude, как чек-ин. Выводы — по просьбе, в недельном обзоре и строкой в вечернем итоге; в сессии `тренер` фраза «срыв: ...» выполняет ту же команду.
- Тест реакции: `coach pvt` — 3 минуты PVT-B в терминале (не в сессии `тренер`): пробел на стимул `●●●`, пауза 1–4 с, провал — реакция дольше 355 мс, фальстарт — раньше 100 мс; итог — медиана, среднее, медленные 10 %, скорость (среднее 1/RT), провалы, фальстарты, проб; до 04:00 — вчера. Просмотр `coach log pvt [--date D]`, MCP `get_pvt_log(date_from, date_to)` (без сырых времён). Тренер только копит. Напоминание — ежедневное событие «Реакция 3 мин» в календаре коуча по просьбе.
- Долг сна: MCP `get_sleep(date)` и ключ `sleep` в утренней сводке — личная норма (медиана ночей за 90 дней, от 20 ночей), долг за 7 и 14 ночей (со знаком; дневной сон гасит долг), короткая ночь (короче нормы на 1 ч), подъём `wake_at` и `caution_from` (подъём + 16 ч) в виде `ГГГГ-ММ-ДД ЧЧ:ММ`, часов от подъёма `awake_h`; у дневных оценок `get_focus_log` — тоже `awake_h`. Данные берутся из ответа Garmin в базе, новых запросов нет; пороги — догадка.
- Возможно, заболеваешь: MCP `get_illness(date)` и ключ `illness` в утренней сводке — пульс покоя и HRV за ночь против личного коридора (среднее за 7 дней ± 0,5 SD за 28 дней, от 14 дней данных); день вне коридора — пульс выше и HRV ниже, 2 дня подряд — сигнал `illness_risk` (предвестник на 1–2 дня, не диагноз). Контекст: короткая ночь, тренировка вчера, долг сна. При сигнале тренер называет цифры, спрашивает о симптомах, предлагает на 2–3 дня снять интенсивное (черновики — после «да») и лечь раньше; «разложи день» ставит фокус-блоков на один меньше; новых запросов к Garmin нет, пороги — догадка.
- Благополучие WHO-5: опросник ВОЗ из пяти утверждений о последних двух неделях (каждое 0–5, балл = сумма × 4, 0–100), раз в 2 недели: `coach who5 <5 цифр> ["текст"]` (до 04:00 — вчера), просмотр `coach log who5 [--date D]`, MCP `get_who5(date_from, date_to)`, ключ `who5` в утренней сводке (`score`, `prev_score`, `delta`, `days_since`, `due` — пора, `low_until`, `signals`). Сигналы: `who5_low` — 28 и ниже (красный флаг: совет к специалисту), `who5_reduced` — 50 и ниже, `who5_drop` — падение на 10 баллов и больше; пороги фиксированы (Topp и др., 2015). WHO-5 © ВОЗ, CC BY-NC-SA 3.0 IGO, использование некоммерческое; русский перевод — ВОЗ, вариант 1999 г. Справка — `.claude/agents/coach-help/who5.md`. Сводка теперь до 32 768 символов, `wellbeing` в ней — за 7 дней (история — `get_wellbeing`).
- Общая нагрузка и перегруз: `get_overload(date)` — `total` (одно число из тренировок, работы, хобби, вечеров/выходных, туду и груминга; часы работы и хобби: ручные > экран > календарь) и сигналы `total_streak`, `evening_streak`, `weekend_work`, `recovery_drop`, `todo_growth`. Веса и пороги — константы в `load/overload.py` (стартовые, пересматриваются по 2-3 неделям данных), формула — в `docs/architecture.md`. В сводке: `overload`, `evening_done_today`, `workload_ahead[].overloaded`.
- Недельный обзор: `get_weekly_review(weeks=4)` (1-12) — ISO-недели Пн-Вс от старой к новой, последняя неполная (`partial`): TSS, общая нагрузка, часы работы/вечера/выходных, туду, средние mood/stress/сон/readiness и `delta` к предыдущей неделе; выводов в коде нет. В сводке `week_review_due` — в воскресенье (текущая неделя) и понедельник (прошедшая), пока нет записи; тренер проводит обзор по `.claude/agents/coach-week.md` и отмечает его `coach review done [--week <понедельник>] ["заметка"]` (по умолчанию: в понедельник — прошедшая неделя, иначе текущая; до 04:00 — как у `coach feel`; повтор обновляет отметку, без новой заметки старая сохраняется).
- Календарь коуча (запись тренера): отдельный календарь в iCloud, его точное название — в `workload.toml`: `[coach] calendar = "<название>"` (то же название нельзя указывать в `[calendar]`). Тренер пишет в `coach_events` только черновики (MCP `create_draft_event`, `cancel_draft_event`; чтение — `get_agenda` и `agenda` в сводке), в календарь их кладёт CLI после «да»: `coach event list [--from D] [--to D]`, `coach event write <id> ...`, `coach event remove <id> ...`, `coach event cancel <id> ...` (черновик). `write` и `remove` не в allow — Claude Code спросит ещё раз. Права на запись нет отдельного промпта: тот же терминал, что и для чтения календаря. Событие, пропавшее из календаря, после `coach sync` помечается снятым; добавленные руками в календарь коуча события пропускаются. Часы событий `task` с категорией work/hobby/personal попадают в нагрузку, тренировки, практики и чек-ин — нет, отдых и сон — `rest`. Правка события — снять и создать новое.
- План дня: MCP `create_day_plan(date, tasks, training_at, ...)` раскладывает день черновиками вокруг занятого (календари и события тренера): тренировка, задачи, готовка перед завтраком и ужином, завтрак, перекус, отдых, ужин, фокус; рамка будни 10:00–00:00, сб/вс 11:00–00:00. Виды `focus` и `meal` в нагрузку не входят. Триггер «спланируй день/завтра» (`.claude/agents/coach-day.md`), в календарь — после «да» командой `coach event write`. Активные пункты туду — `coach todo list` (только чтение, названия в базу не попадают).
- Роль тренера собрана из файлов: ядро `.claude/agents/coach.md` (до 15 КБ) и подгружаемые по требованию `coach-wellbeing.md` (нагрузка, выгорание), `coach-nutrition.md` (спортпит, добавки, витамины, кладовая и рецепты), `coach-week.md` (недельный обзор), `coach-agenda.md` (календарь коуча), `coach-onboarding.md` (профиль); вечерний чек-ин — скилл `coach-evening`.

## MCP и скиллы тренера (Claude Code)
- MCP-сервер (stdio) читает агрегаты из базы (без raw_json); списки отдаются как `{rows, truncated}`, до 60 строк и 20 000 символов, у рядов по датам остаются самые новые строки. Пишет только черновики: `create_draft_workout`, `cancel_draft_workout` (только draft -> cancelled), `propose_phase`. Инструментов отправки на часы и удаления нет, в Garmin сервер не ходит: утверждает и отправляет пользователь (`coach approve`, `coach push`); отменяет утверждённую и отправленную тоже он (`coach cancel <id>`, у отправленной - после y/N, со снятием с календаря и удалением из Garmin).
- Регистрация (один раз; путь к репо свой):
  `claude mcp add ai-coach -- uv run --project /путь/к/ai-coach python -m ai_coach.mcp_server`
  База — `$AI_COACH_DB` или `~/.local/share/ai-coach/coach.db`.
- Нагрузка (CTL/ATL): пульс покоя берётся из ответа сна в базе (последний день с данными, не старше 14 дней, иначе ошибка «сделай coach sync»). Пороговый пульс (LTHR) свой для каждого вида (бег/вело/плавание), таблица `thresholds` с историей: `coach sync` забирает беговой порог (endpoint `latestLactateThreshold`, source `garmin_lt`) и пороги видов из пульсовых зон Garmin (`get_heart_rate_zones`, source `garmin_zones`). Чего Garmin не дал, считается на лету (source `derived`): беговой минус смещение (вело −7, плавание −12, константы в `load/thresholds.py`), а без бегового порога — 0.89 × максимальный пульс из активностей. Силовая — 35 TSS/час, растяжка — 0, незнакомый вид — по беговому порогу. `get_load` отдаёт `thresholds` ({вид: {lthr, source, date}}), снапшот — тоже. Нет данных — в снапшоте `load_error`, остальное работает.
- Скиллы лежат в `.claude/skills/` и подхватываются в этом репозитории: `/coach-morning` (утренний разбор и рекомендации по восстановлению, Sonnet), `/coach-plan` (план недели черновиками, Sonnet; форматы тренировок в `.claude/skills/coach-plan/spec-formats.md`), `/coach-food` (раз в день считает КБЖУ записей еды без него, Sonnet). Поле `model` во frontmatter и имена инструментов `mcp__ai-coach__*` в `allowed-tools` на живом Claude Code не проверены.

Справка по функциям тренера: в сессии `тренер` спросите «что умеешь», «как ...» или «что значит ...» (шкала, число, поле) — тренер отвечает по темам из `.claude/agents/coach-help.md` и `.claude/agents/coach-help/`. Новая функция — правка справки в том же шаге; полноту имён команд, инструментов и скилов держит `tests/test_skills_help.py`.
