# Версия 2: веллбиинг-коуч — ТЗ

Статус: **черновик ТЗ**, ред. 4 (2026-10-10). Влад утвердил направление; вход цепочки кабанов (свинопас ‖ кабан-шурин → папа-кабан → кабан-тесть → аппрув).

## Источник и цель

Идея — карточка дашборда `~/projects/dashboard/ideas/wellbeing-coach.md` («Велбинг-коуч», priority high): коуч смотрит на нагрузку целиком — работа, нагрузка вне тренировок, хобби, отдых, общая нагрузка как их сумма. В документах ai-coach про v2 ничего не было.

**Главная проблема Влада — подступающее выгорание.** Цель v2 — регулировать объём и нагрузку на организм: видеть общую нагрузку (тренировки + работа, её много, + хобби) против восстановления и вовремя её снижать.

## Решения Влада (2026-10-10, через супервизора)

1. Опоры: сон, стресс, настроение (ментальное), привычки, **загруженность** — работа, хобби, баланс работы и отдыха. Ядро — календарь и общая нагрузка, нужны инсайты.
2. Один агент: расширяем `тренер`, отдельного не делаем.
3. Ритм: утренний разбор + вечерний чек-ин.
4. Ментальное: только оценки настроения и стресса и практики; дневника и КПТ нет.

Ред. 3 (2026-10-10):

6. В рабочую нагрузку входят ещё **рабочий туду** и **ответы на вопросы груминга** (заявки doc-tool в hb-doc).
7. Привычки отложены — остаются в v2.4.
8. События календаря хранятся с названиями; база вне репо.

Ред. 4 (2026-10-10, по вопросам свинопаса):

Ответы на вопросы карточки дашборда: расширение ai-coach (новые модули); коуч советует, предупреждает о перегрузе и перестраивает план тренировок черновиками (как в v1); источники данных о работе — Apple Calendar, рабочий туду, ответы по грумингу.

## Источники рабочей нагрузки (найдено, способ подсчёта — вопрос 1)

| Источник | Где | Что считать (предложение) |
|---|---|---|
| Apple Calendar | Calendar.app на маке; доступ — EventKit (Swift-хелпер или `pyobjc-framework-EventKit`) либо `icalBuddy`; macOS спросит разрешение на календарь | Часы встреч, их число, работа вечером (после 19:00) и в выходные; работа/личное — по календарю-источнику |
| Рабочий туду | `~/.claude/todo.json` (скил whats-up): `state` todo/doing/done/dropped, `created`/`updated` | Число открытых (todo + doing) на дату и закрытых за день — как «хвост» нагрузки |
| Ответы по грумингу | Вопросы к Владу — файлы `GQ-VA-*` в `~/msa/hb-doc/analysis/*/04-grooming/`; обработанные упоминания hb-answer переносит в `~/bin/hb-watch/done/` (67 шт., из них 8 — ответы на GQ; при ответе PR дописывается строка `pr:` и меняется mtime), очередь — `pending/` | Обработанных за день (по mtime всех файлов `done/`, п. 13) и сколько висит в `pending/`. Туду: «открытых на конец дня» — только снимком при ежедневном sync (истории в `todo.json` нет), «закрытых за день» — по `updated` у done/dropped |

Всё только читается, в hb-doc и туду ai-coach ничего не пишет. В базу ai-coach — только счётчики по дням (без текста рабочих вопросов). Это сознательное исключение из правила «не смешивать hb-doc с ai-coach» — по слову Влада.

## Что меняется относительно v1

| | v1 | v2 |
|---|---|---|
| Нагрузка | Только тренировки: TSS → CTL/ATL | **Общая нагрузка за день/неделю** = тренировки + работа (встречи из Apple Calendar, вечера/выходные, открытый туду, ответы по грумингу) + хобби; тренд против восстановления |
| Восстановление | Сон, HRV, BB, readiness, самочувствие 1–5 | То же + вечерние оценки настроения и стресса |
| Риск выгорания | Нет | Сигнал перегруза: высокая общая нагрузка несколько дней подряд + падение восстановления/настроения; пороги — константы модуля, как в шаге 10 |
| Реакция | Пересчёт плана при плохом восстановлении | + снизить объём тренировок черновиком, предложить отдых/«пустой» вечер, указать перегруженные дни календаря на неделю вперёд |
| Ритм | Утренний разбор | + вечерний чек-ин: настроение, стресс, работа/хобби/отдых за день (короткие оценки) |
| Стресс | Метрики Garmin | + короткие практики (дыхание, пауза), подбор по стрессу/BB |
| Привычки | Нет | Небольшой трекер (состав — вопрос 2) |
| Недельный обзор | План недели | + обзор нагрузки и баланса работы/отдыха, инсайты |
| Тренировки, еда, спортпит, курсы | — | Без изменений |

Принципы v1 остаются: данные в SQLite через CLI/MCP, логика в промптах; MCP только читает и пишет черновики; на часы отправляет только Влад; календарь только читаем.

## Этапы

Каждый этап — по циклу «Общее для шагов 2–8» в `plan.md`: груминг, план папы-кабана, TDD, ревью, аудит.

1. **v2.0 — спайк источников:** Apple Calendar через EventKit за 30 дней (разрешение macOS, поля, какие календари рабочие/личные/хобби); чтение `todo.json` и `hb-watch/done|pending` — достаточно ли mtime для «ответов за день». Отчёт — без личных данных.
2. **v2.1 — загруженность:** импорт событий с названиями в базу (`calendar_events`, синк в составе `coach sync`), классификация работа/хобби/отдых; счётчики туду и груминга по дням (`work_counters`); метрики дня: часы встреч, вечера/выходные с работой, открытый туду, ответы по грумингу. MCP `get_workload`, раздел в snapshot.
3. **v2.2 — вечерний чек-ин:** оценки настроения и стресса (расширить `wellbeing_log`), ручная отметка работы/хобби/отдыха там, где календаря нет; скил `/coach-evening`, вход из `тренер` вечером.
4. **v2.3 — общая нагрузка и сигнал выгорания:** модуль `load/` + общая нагрузка, пороги перегруза, реакция в агенте (снижение плана черновиками, разгрузка), прогноз по календарю на неделю.
5. **v2.4 — практики и привычки:** справочник практик стресса/сна (как рецепты), трекер привычек (состав выбирается на груминге v2.4).
6. **v2.5 — недельный обзор и агент:** инсайты (нагрузка ↔ сон ↔ настроение), роль коуча в `coach.md` с выносом частей в файлы (лимит размера промпта ~15 КБ).

## Открытые вопросы к Владу

Отвечены в ред. 3 (календарь, привычки, хранение, релиз). Остался один, его можно решить на спайке v2.0:

1. **Подсчёт туду и груминга:** туду — «открытых на конец дня» + «закрытых за день»; груминг — «ответов за день» по mtime файлов в `hb-watch/done/` (если mtime ненадёжен — по истории коммитов Влада в hb-doc в `04-grooming/`). **Решение Влада (2026-10-10): считать так, для начала хватит.** Модель нагрузки делать расширяемой: позже добавятся собственное ощущение загруженности и другие признаки — новый признак добавляется без переделки (счётчики по дням с видом признака, а не отдельная колонка на каждый).

Модель и деньги — по умолчанию как в v1 (Sonnet); кабан-тесть оценивает план каждого этапа (вечерний чек-ин — на v2.2).
