# Шаг Н36. Повторы по дням в `coach event list` и MCP `get_agenda` (BACKLOG 57)

План — папа-кабан, 2026-11-25. Контур: вне msa; режим: встроить. Разведка на HEAD 3b5f040 (Read кода, grep, живая база

## Суть

Повторяющееся напоминание хранится одной строкой `coach_events` на серию (дата и время — первого вхождения).
`agenda_rows` (`agenda/service.py:175`) кладёт все активные серии, начатые раньше периода, в начало списка с исходной
датой и не проверяет, выпадает ли серия на дни периода. Пульт раскладывает повторы по дням сам (`web/day.py:54-55`,
функции `on_day` и `moved` из `web/repeat.py`); `coach event list` и `get_agenda` — нет. Шаг даёт списку и
инструменту ту же раскладку, что у пульта, одной общей функцией. Какая именно раскладка — видимое, решает Влад
(`docs/plan-p1.md:196-197`, «Правки по ревью» п. 1, 2026-11-07).

**Правило** (первый пункт аппрува), при Р1 = 1 и Р2 = 1:

1. Было (`cli/agenda.py:83`): `rows = agenda_rows(conn, first, last)` → станет:
   `rows = agenda_by_day(conn, first, last)`.
2. Было (`mcp_server/agenda.py:135`): `return cap(agenda_rows(conn, date_from, date_to))` → станет:
   `return cap(agenda_by_day(conn, date_from, date_to))`.
3. `agenda_by_day` (новая, `agenda/service.py`): строки `agenda_rows` без повтора — как есть; строка с повтором —
   по одной на каждый день периода, начиная с даты серии, на который серия выпадает (`on_day`), с временем этого дня
   (`moved`) и `date` этого дня; порядок — по `start_at`, затем `id`.
4. Не меняется: `agenda_rows` (её читают `agenda/slots.py:45`, `agenda/day_plan.py:81,135`,
   `mcp_server/snapshot.py:228`), схема `coach_events`, правила создания повторов (`agenda/draft.py:85-128`), запись в
   календарь, период `coach event list` по умолчанию (30 дней назад — 14 вперёд), лимиты MCP (60 строк, 20000
   символов, 92 дня).

При Р1 = 2 или 3, Р2 = 2 или 3 правило другое — см. варианты в «Развилках»; «Файлы» и «Тесты» правятся после ответа.

**Поведение:** меняется — где: (а) `coach event list`: напоминание стоит строкой в каждом своём дне на своём
времени, а не одной строкой сверху с датой начала серии; еженедельное и двухнедельное не видны в чужие дни; (б)
`get_agenda`: то же для тренера, `date` у строки повтора — день вхождения; (в) пульт, `agenda` в утренней сводке, план
дня, свободные окна — не меняются.
**Вне репо:** нет. Строк allow не нужно: новых команд и файлов справки нет.
