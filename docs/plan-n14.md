  `tool_names(conn) - allowed == set()` (Н1 партия 2).

Что строим: справка — набор файлов по областям, которые тренер читает `cat` по вопросу Влада (как `variety.md`),
оглавление в файле роли, триггер в `coach.md`; тест полноты по именам команд и инструментов; правило проекта
«функция и справка — в одном шаге».

**Правило:** было `test_every_mcp_tool_is_in_coach_md_tools`: `tool_names(conn) - allowed == set()` (полнота только
по `tools:` в `coach.md`) → станет: плюс `tool_names(conn) - mentioned(help) == set()` и
`cli_commands(app) - mentioned(help) == set()`, где `help` — `coach-help.md` + `coach-help/*.md`, `cli_commands` —
обход typer-дерева (новый `tests/test_skills_help.py`). Процессное правило — AGENTS.md «Местные правила»: шаг с новой
или изменённой функцией правит справку в том же шаге; план шага без пункта «Справка» неполный.
**Поведение:** меняется — тренер на «что умеешь / как … / что значит …» читает файл справки и отвечает по нему
(сейчас — по памяти промпта); при Р3 = (3) меняется строка «что умею» в сводке; при Р6 = (1) заметка трёх напоминаний
«Фокус 1–5?» получает расшифровку шкал. Код `src/` не меняется (при Р4 = (1)); данные, снапшот, MCP — без правок.
**Вне репо:** при Р6 = (1) — Влад говорит «да» на пересоздание трёх событий в календаре коуча (`coach event remove`
+ новые черновики + `coach event write`, обе команды не в allow — так задумано v2.6). Новых зависимостей нет;
MCP-сервер не меняется, перезапуск не нужен.

## Развилки и риски

Видимое Владу — развилки, решает Влад. Первая — блокирующая для `wellbeing.md` (партия 1).

- **Р5. Полюса шкал 1–5** (`cli/main.py:274-285`, `cli/journal.py:136`; сейчас нигде не записаны). Рекомендую «больше
  — больше названного»: самочувствие 1 плохо – 5 отлично; настроение 1 плохое – 5 отличное; стресс 1 нет – 5 сильный
  (уже так: `coach-evening/SKILL.md:12`); фокус 1 рассеян – 5 полностью собран; умственная усталость 1 свеж – 5
  выжат; усилие 1 легко взялся – 5 через силу; мысли о работе 1 не думал – 5 всё время (уже так, :15); помехи 1 почти
  не было – 5 весь день; ценность 1 почти ничего – 5 всё ценное. Альтернатива — «5 = хорошо» у всех (тогда усталость
  5 = свеж, стресс 5 = спокоен) — ломает `find_deviations` (`stress >= 4` — плохо) и существующие тексты. Направление
  фокуса и усталости важно для профиля Н9: разнобой в ответах портит данные с первого дня (r1 «Почему здесь» а).
- **Р1. Где живёт справка.** (1) `.claude/agents/coach-help.md` + `coach-help/<тема>.md`, тренер читает `cat` по
  триггеру — прецедент `coach-nutrition/variety.md`, тесты текстов и allow уже смотрят в `.claude/`. (2)
  `docs/howto-coach-<тема>.md` (COMMON «Инструкции для людей») — те же `cat`, читаемо в `docs/`, но тесты `.claude`
  и правило «файлы роли — в agents» расходятся с местом. (3) MCP `get_help(topic)` — отказ: сервер читает только
  базу (architecture.md «Разделение»), чтение файлов — новый тип инструмента, перезапуск сервера на каждую правку
  текста. Рекомендую (1).
- **Р2. Формат карточки функции.** (1) Пять полей из BACKLOG 27: «Что это · Зачем · Как запустить (команда / фраза
  тренеру) · Как заполнять (шкалы, смысл чисел) · Что получу и когда»; опции команд не дублировать — ссылка
  «подробности опций: `coach <команда> --help`». (2) Таблица «команда — что делает» без «зачем» и «что получу» —
  короче, но это уже есть в `--help`. Рекомендую (1).
- **Р3. Как тренер отвечает.** (1) Только по вопросу: триггеры «что умеешь», «как …», «что значит …», «справка»,
  «помощь» → `cat coach-help.md` → `cat` нужной темы → ответ ≤ 10 строк с командой или фразой, в конце «подробнее?».
  (2) Плюс проактивно при первом использовании функции — нужно состояние «уже объяснял», в Н14 не берём. (3) Плюс
  строка «что умею» в сводке получает хвост «— спроси „справка“ или „что значит …“» (пересмотр решения Влада
  2026-10-08 «строкой в каждой сводке», docs/plan.md:371 — слова остаются, добавляется подсказка). Рекомендую (1) + (3):
  ранний признак К1 из r1 — «Влад спрашивает тренера и получает ответ из справки», без подсказки справку не позовут.
- **Р4. Справка без тренера.** (1) Файлы читаемы в репо и на GitHub, по командам есть `coach <команда> --help`;
  новой команды нет. (2) `coach help [тема]` печатает файл темы — новая функция `cli.help:help_` (~30 строк, тесты,
  mutmut), читает `.claude/agents/coach-help/` относительно репо (команда и так запускается `uv run` из репо).
  Рекомендую (1): минимум; (2) — пункт бэклога, если Влад станет открывать справку без `тренер`.
- **Р6. Заметка напоминаний «Фокус 1–5?».** (1) Дописать полюса трёх шкал по Р5 в заметку (`coach-agenda.md:15`) и
  пересоздать три живых события (remove → черновики → write, «да» Влада). (2) Оставить только команду. Рекомендую (1):
  напоминание — место, где Влад вводит цифры без тренера; вариант 3 из r1 (`plan-roadmap-r1.md:237`) предлагал то
  же.

Риски:

- Точность текста: тест полноты проверяет имена, не смысл; расхождение справки с кодом ловит только ревью мамы —
  кабану писать по коду и `--help`, не по памяти; в карточке — ссылка на `--help`, не копия опций.
- Дрейф: функция меняется, справка нет — правило AGENTS.md + тест полноты (новая команда без упоминания — красный);
  изменение смысла без смены имени тест не ловит — пункт «Справка» в каждом плане шага с Н13.
