# Шаг Н35. «Пропущено» у сегодняшней тренировки до её времени (BACKLOG 65)

План — папа-кабан, 2026-11-25. Контур: вне msa; режим: встроить. Разведка на HEAD f297171 (Read кода, grep, живая база
только на чтение). Состояние: принят Владом 2026-11-25 («кабаним»), Р1–Р3 решены («Решения»).

## Суть

`coach sync` пересчитывает `plan_actual` за окно дней до сегодня включительно (`sync/garmin_sync.py:271`). Отправленная
на часы тренировка сегодняшнего дня, у которой ещё нет активности, получает строку `skipped`
(`load/plan_actual.py:79`). Живая база 2026-11-25: строка `skipped` за сегодня создана синком в 10:25. Её читают все:

- пульт, окно тренировки — плашка «пропущено» (`web/training.py:100` `fact` → `training-pane.js:94`);
- пульт, вкладка «Тренировки» — плашка «пропущено» вместо «на часах» (`web/training.py:138` `week` →
  `week-model.js:24`);
- тренер — `get_plan_actual` (`mcp_server/tools.py:166`), `plan_actual` в сводке (`mcp_server/snapshot.py:197`), счёт
  `skipped` за 7 дней (`.claude/skills/coach-morning/plan-actual.md:5`);
- журнал решений — `result = missed` у решения о тренировке (`mcp_server/decisions.py:12`, `_result`).

Чинится источник, а не каждый читатель (П3, Р31 = 1, решил Влад 2026-11-09, `docs/plan-p3.md:58`: «причина в данных —
BACKLOG 65»; вариант «прятать на вкладке» там же отклонён — окно и вкладка разошлись бы).

**Правило** (первый пункт аппрува), при Р1 = 1 и Р2 = 1:

1. Было (`load/plan_actual.py:74-79`): у любого дня окна план без активности своего вида получает
   `add_plan_actual(conn, _row(date, "different", …))`, если в дне есть свободная активность, иначе
   `add_plan_actual(conn, _row(date, "skipped", planned["id"], None))` → станет: то же, но только при
   `date != today`; у дня `date == today` такой план остаётся без строки, свободные активности дня пишутся `extra`.
   Пары «план — активность своего вида» (`done`, у силовой `different` с `missing_exercises`) пишутся и сегодня.
2. Было (`sync/garmin_sync.py:271`): `rebuild_plan_actual(conn, day_list[-1], day_list[0])` → станет:
   `rebuild_plan_actual(conn, day_list[-1], day_list[0], today.isoformat())`.
3. Не меняется: схема `plan_actual` и её CHECK, виды `done / skipped / extra / different`, слова плашек, код пульта
   (`web/*`, `static/*`), код MCP, кроме одной строки описания инструмента.

**Поведение:** меняется — где: (а) вкладка «Тренировки», сегодняшний день: «на часах» вместо «пропущено», пока нет
активности; (б) окно тренировки сегодня: вместо плашки «пропущено» — как у тренировки без факта (до начала «Ещё не
началось.» и шаги, после начала шаги и кнопки «Сделал / Пропустил», после конца ещё подсказка Р25 про `coach sync`);
(в) красная строка пункта не меняется (`web/day_marks.py:71`: «нет факта» и `skipped` равны); (г) тренеру за
сегодня приходят только `done`, `different` у силовой и `extra`; (д) «пропущено» и `missed` появляются при первом
синке на следующий день.
**Вне репо:** нет. Строк allow не нужно: новых команд нет.

## Развилки

Видимое пользователю; решает Влад. Макета в репо нет, слова плашек — из решений П3 (`docs/plan-p3.md:56-58`).

- **Р1. Когда у тренировки появляется «пропущено».**
  (1) По дню: в день тренировки строки `skipped` нет, плашка «на часах» держится до конца суток; «пропущено» — при
  первом синке на следующий день. Правка — одно условие в `_rebuild_day` и параметр `today`.
  (2) По времени пункта дня: `skipped` пишется синком, прошедшим после конца пункта тренировки (`coach_events.end_at`);
  у тренировки без пункта дня — как в варианте 1. Пункт дня есть у 17 из 34 отправленных тренировок живой базы, то
  есть половина всё равно пойдёт по варианту 1; `load/*` начинает читать `store/agenda`, нужен параметр «сейчас»;
  объём — ожидание, не проверено: 30–40 строк кода и вдвое больше тестов. «Пропущено» вечером появится, только если
  после конца пункта был синк.
  (3) Не трогать данные, прятать `skipped` за сегодня у читателей: пять мест (`web/training.py` `fact` и `week`,
  `mcp_server/tools.py` `plan_actual`, `snapshot.py`, `decisions.py` `_result`). Противоречит Р31 П3 («причина в
  данных»).
  Рекомендую 1 — день ещё не кончился, тренировку можно сделать и после времени пункта; одно правило для всех
  тренировок, с пунктом дня и без. Зависят: «Правило», «Файлы», «Тесты», Р3, «Умолчания» п. 3–4.
- **Р2. «Выполнено иначе» сегодня, когда есть активность другого вида.** Сейчас план без пары своего вида забирает
  первую свободную активность дня (`plan_actual.py:75-77`): утренний заплыв делает вечерний бег «выполнено иначе» ещё

  (1) Сегодня план без пары своего вида строки не получает, чужая активность — строка «вне плана»; назавтра синк
  пересчитает: план — «выполнено иначе», строка «вне плана» исчезнет. Цена: плашка той же активности меняется на
  следующий день.
  (2) Чинить только `skipped`: при чужой активности сегодня «выполнено иначе» пишется сразу, как сейчас.
  Рекомендую 1 — одна причина, одно правило: день не закрыт — план не оценивается. Зависят: «Правило» п. 1, «Тесты»
  (сценарий с заплывом).
- **Р3. Фраза в справке** (`coach-help/training.md`, «План и факт», после строки «В пульте», `:28`), при Р1 = 1:
  (1) «„Пропущено“ появляется на следующий день после `coach sync`: в день тренировки, пока активности нет, она
  остаётся „на часах“.»
  (2) Без фразы в справке — только правка описания инструмента для тренера. Нарушает правило AGENTS.md «Справка».

  тренировки; у тренировки без пункта дня — на следующий день.» Зависят: «Файлы» (`training.md`), «Справка».
