## Суть

Влад отмечает в пульте «Сделал / Пропустил» у практики, отдыха, тренировки и чек-ина «без анкеты». Отметка лежит в
`done_log`, читает её только пульт: тренер не знает, сделана ли практика, которую он сам поставил (BACKLOG 107).
Попутно: описание `get_agenda` называет шесть видов событий из восьми (BACKLOG 106); правка текста
`coach-agenda.md` при запасе 155 Б требует выноса части текста (BACKLOG 108, местное правило AGENTS.md).

**Правило** (первый пункт аппрува):
1. 107: было — `list_done` зовётся только из `web/marks.py:182` (`marks_for_day`), в `mcp_server/` обращений к
   `done_log` нет (`grep -rn done_log src` — только `store/agenda.py` и миграция 0029) → станет (при Р1 = 2) — новый
   инструмент MCP `get_done_log(date_from, date_to)`: `agenda.done_log` (новая) → `cap(list_done_events(...),
   newest=True)`, `list_done_events` (новая, `store/agenda.py`) — `done_log JOIN coach_events`. При Р1 = 1 или 3
   правило меняется в другом месте — см. Р1.

   `mcp_server/server.py:310`) → станет — `"... id, kind (" + "/".join(KINDS) + "), title, date, "`, `KINDS` —
   `agenda/service.py:26` (восемь видов). Склейка из константы — как `", ".join(FOOD_GROUPS)` в том же файле
   (`server.py:352`).

**Поведение:** меняется — тренер получает отметки «сделал / пропустил» (где и что с ними делает — Р1, Р2); описание
`get_agenda` называет `focus` и `meal`. Не меняется: пульт, база (миграций нет), CLI, `agenda_rows`, сводка (при
Р1 ≠ 3), `load/*`. Правило окна v2.9 цело: `done_log` только читается, записи не переписываются.
**Вне репо:** Влад добавляет в `.claude/settings.json` строку allow `Bash(cat .claude/agents/coach-agenda/errors.md)`

## Развилки

Р1–Р4 — о том, что тренер знает и говорит; это видит Влад в разговоре. Выбор за Владом.

**Р1. Где тренер видит отметку.**
1. Поле в строках `get_agenda`. У обычного события — `done` (1 / 0 / null) за его день. У повторяющегося чек-ина
   строка одна на все дни — нужен список `[{date, done}]` за период. Нового инструмента нет, `coach.md` не
   растёт. Минусы: два вида поля в одном ответе; строки тяжелее, раньше срабатывает обрезка (60 строк / 20000
   знаков); схема существующего инструмента меняется.
2. Отдельный инструмент `get_done_log(date_from, date_to)` — журнал отметок за период, строка на отметку: `date`,
   `event_id`, `kind`, `title`, `done`, `logged_at`. Как `get_habit_log`, `get_focus_log`, `get_slip_log`. Повтор
   ложится без особого случая. Минусы: ещё один инструмент; шапка `coach.md` +29 Б при запасе 90 Б (останется 61).
3. В утренней сводке: `done` в строках `agenda` у `get_morning_snapshot` (вчера и сегодня). Тренер видит без
   отдельного вызова. Минусы: только вчера и сегодня — неделю назад не видно; та же трудность с повтором, что в 1;
   растёт сводка с общим лимитом знаков.
4. 2 и 3 вместе.

Рекомендую 2: так уже устроены все журналы отметок, код — два десятка строк, `agenda_rows` и сводка не трогаются.
3 имеет смысл только вместе с Р2 = 2.
