## Суть

Тренер замечает слабое место системы (пример — его сообщение, из которого выросли BACKLOG 81–84) и сейчас может
передать его только словами Владу. Шаг даёт тренеру канал: он сам записывает отчёт, технический агент (сессия Claude

**Правило** (первый пункт аппрува):

   list|add|start|done|drop|reopen|edit`» — команды отчёта нет, о проблеме системы тренер только говорит → станет
   (при Р1 = 1, Р2 = 1): в тот же перечень добавляется `report add`, в «Порядок разговора» — пункт 9з со ссылкой на
   боковой файл.

   ROADMAP выполняют `uv run coach report list`; открытый отчёт переписывают своими словами в пункт BACKLOG (без
   значений и дат самочувствия) и закрывают `uv run coach report done <id> --backlog <N>`.

   трогается; при Р2 = 2 эта фраза дополняется именем нового инструмента.

`coach.md` часть текста уезжает в боковой файл (Р7).

**Р1. Канал: куда тренер кладёт отчёт** (ключевая; хранилище и внешний сервис).
(1) Локальная очередь в базе: `coach report add` пишет строку в `system_report`; технический агент читает `coach
report list`, сам пишет пункт BACKLOG и закрывает отчёт с номером пункта. Отчёт не публичен, пока его не переписал
технический агент; беклог остаётся единственным реестром (RULES, дашборд); образец — `decide add`. Цена: правило в
AGENTS.md (Р9) и запись `report done` техагентом в живую базу.
(2) Сразу пункт в `docs/BACKLOG.md`: команда дописывает `## N.` в конец файла. Без посредника, но текст тренера сразу
в публичном репо — между ним и `git push` только фильтр (Р3) и внимание того, кто коммитит; рабочее дерево после
