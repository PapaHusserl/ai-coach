# Шаг 24. Микронутриенты: разнообразие по группам продуктов

Закрывает BACKLOG 6. План — папа-кабан, 2026-10-19, по ресёрчу дяди-кабана и решениям Влада.
В код — после шага 23 (планка); с v2.7 по коду не пересекается (питание, не нагрузка).

## Суть

Миллиграммы витаминов и минералов не считаем: тренер при расчёте КБЖУ (`coach-food`) относит каждую
запись еды к группам продуктов (рыба, бобовые, зелень, молочное, орехи, красное мясо…); код считает по
неделе, в сколько дней какая группа была; группы ниже порога дают сигнал «мало рыбы → мало D / омега-3».
Тренер показывает сигналы в недельном обзоре и по запросу, предлагает разнообразие или добавку — в
пределах верхних допустимых уровней по МР 2.3.1.0253-21, без мегадоз.

**Правило:** новое. `save_food_nutrition` (`mcp_server/tools.py`) пишет только КБЖУ → станет: вместе с
КБЖУ пишет группы записи (`groups`, список из фиксированного словаря); `variety_week(conn, monday)`
(новая) считает дни с группой за неделю и список групп ниже порога с подсказкой по нутриентам.
**Поведение:** меняется — `coach-food` после шага пишет группы; записи до шага без групп (решение в
вопросах); недельный обзор получает блок разнообразия.
**Вне репо:** нет (нормы — константы в коде; внешних сервисов и баз нет).

## Решения

1. 2026-10-19, Влад: без базы нутриентов — только разнообразие. LLM относит блюда к группам продуктов,
   тренер смотрит неделю и даёт сигналы «нет рыбы → мало D / омега-3»; миллиграммы не считаем.
2. 2026-10-19, Влад: плюс рекомендации по бадам — с учётом верхних пределов, без мегадоз.
3. 2026-10-19, Влад: нормы — российские МР 2.3.1.0253-21 (Роспотребнадзор, 2021).
4. 2026-10-19, Влад: Open Food Facts не нужен — штрихкодов в записях нет.
5. 2026-10-19, Влад (вопрос 1): словарь — 11 групп, без субпродуктов (`organ_meat` не берём).
6. 2026-10-19, Влад (вопрос 4): пороги — стартовые как предложено (рыба 2, бобовые 2–3, зелень/овощи 5+,
   молочное 5+, орехи 3+, красное мясо ≤ 3), калибровка по 3–4 неделям.
7. 2026-10-19, Влад (вопросы 2, 3, 5–8): все рекомендации папы-кабана — таблица `food_group`; старые записи
   не размечать; `groups` в `save_food_nutrition`; сигналы в недельном обзоре и по запросу; нормы
   «мужчины 18–59» константой; нутриент курса — по имени из `get_meds`.

## Модули и функции

Все функции новые, кроме помеченных.

- `src/ai_coach/store/migrations/0020_food_groups.sql` — таблица `food_group (food_id → food_log.id,
  group_key TEXT CHECK (group_key IN (...)), PRIMARY KEY (food_id, group_key))`; словарь групп в CHECK,
  как `kind` в `med_course` (0013). Отдельная таблица, а не колонка: группы — множество, их считают
  по дням SQL-ом.
- `src/ai_coach/nutrition/groups.py` — `FOOD_GROUPS`: ключ → название по-русски → нутриенты, за
  которые группа отвечает (например `fish` → «рыба и морепродукты» → D, омега-3, йод); `GROUP_MIN_DAYS`:
  порог «дней в неделю» на группу (стартовые константы, как веса в `load/overload.py`; калибровка —
  только константы). Источник порогов — см. вопрос 4.
- `src/ai_coach/nutrition/norms.py` — `NUTRIENT_NORMS`: нутриент → (суточная норма, ВДУП, единица) по
  МР 2.3.1.0253-21 для взрослых мужчин (профиль пола/возраста в `profile_log` не хранится — вопрос 7);
  только нутриенты из `FOOD_GROUPS` (~10–12 строк), не вся таблица МР. Для витамина D — и мкг, и МЕ.
- `src/ai_coach/nutrition/variety.py` — `variety_week(conn, monday) -> dict`: по `food_group` ∪
  `food_log` (живые записи, `substr(logged_at,1,10)` по дню как в `list_food`) — `days_with_data`,
  `groups: {key: days}`, `low: [{group, days, min_days, nutrients}]`. Дни — календарные по `logged_at`
  (еда не сдвигается на «вчера» до 04:00 — как сейчас в `list_food`); неделя — ISO Пн–Вс, `monday()` из
  `review/service.py` (есть).
- `src/ai_coach/store/journal.py` — `add_food_groups(conn, food_id, groups)` (только если групп ещё нет,
  по образцу `update_food`), `list_food_groups(conn, start, end)`; `edit_food` (есть, :78) при новом
  тексте сбрасывает КБЖУ — там же удалять группы (запись снова в pending — тренер переразметит).
- `src/ai_coach/mcp_server/tools.py` — `save_food_nutrition` (есть, :506): новый необязательный параметр
  `groups: list[str] | None`; неизвестный ключ → `ToolError` со списком допустимых; пишется в одной
  транзакции с КБЖУ. Новый read-инструмент `food_variety(conn, weeks=1..12, по умолчанию 4 — как `get_weekly_review`)` → `get_food_variety`
  (регистрация в `server.py`, описание со словарём групп); новый `get_nutrient_norms` (без аргументов,
  таблица `NUTRIENT_NORMS`) — чтобы цифры ВДУП брались из кода, а не из памяти модели.
- `src/ai_coach/review/service.py: weekly_review` (есть, :137) — не трогать: разнообразие — отдельный
  инструмент, чтобы не раздувать `get_weekly_review` и его тесты.
- `.claude/skills/coach-food/SKILL.md` — шаг 3: вместе с КБЖУ передать `groups`. Файл 3044 Б при лимите
  3072 (`tests/test_skills_text.py: MAX_BYTES`) — словарь и правила отнесения вынести в
  `.claude/skills/coach-food/groups.md` (как `coach-meal/training-nutrition.md`), в SKILL.md — одна
  строка со ссылкой.
- `.claude/agents/coach-nutrition.md` — новый пункт 8в «Разнообразие»: когда (`get_food_variety` в
  недельном обзоре и по запросу «чего мне не хватает»), как говорить (группа → чем грозит нехватка →

## Тесты (кабан-доеба)

- `add_food_groups` на запись без групп → строки в `food_group`; повтор → False, строки не задвоены;
  неизвестный ключ → ошибка (CHECK), транзакция откатывается.
- `edit_food` с новым текстом → КБЖУ NULL и групп нет; только время → группы на месте.
- `save_food_nutrition(..., groups=["fish","greens"])` → КБЖУ и группы в одной транзакции; `groups` не
  передан → как сейчас; неизвестная группа → `ToolError` с перечнем допустимых, КБЖУ не записано;
  запись с КБЖУ, но без групп → «уже посчитано» (как сейчас).
- `variety_week`: 7 дней, рыба в 1 день при пороге 2 → `low` содержит `fish` с `days=1`, `min_days=2`,
  `nutrients` из `FOOD_GROUPS`; все группы ≥ порога → `low == []`; записей нет → `days_with_data == 0`,
  `low == []` (не шуметь на пустой неделе); удалённая запись (`deleted_at`) не считается; две записи с
  рыбой в один день → 1 день.
- `get_food_variety(weeks=4)` → 4 недели от старой к новой, последняя `partial`; `weeks` вне 1..12 →
  `ToolError` (как `get_weekly_review`).
- `get_nutrient_norms` → у каждой строки есть норма, ВДУП и единица; у витамина D — мкг и МЕ, 1 мкг =
  40 МЕ.
- Тексты: `coach-food/SKILL.md` ≤ 3072 Б и ссылается на `groups.md`; `groups.md` перечисляет все ключи
  `FOOD_GROUPS` (тест сверяет с кодом, чтобы словарь не разъехался); `coach-nutrition.md` упоминает
  `get_food_variety`, `get_nutrient_norms` и верхний предел; `coach-week.md` — `get_food_variety`.
- Руками: `тренер` → «чего мне не хватает по еде» — перечень групп ниже порога с нутриентами и одно
  предложение по еде; добавка — только если еда не закрывает, доза с оглядкой на `get_meds`.

## Риски

- Разметка по группам — оценка модели: «салат» без состава может не попасть в «зелень». Лечится
  правилом в `groups.md` (нет состава — спросить, как с граммами) и тем, что считаем дни, а не граммы.
- Пороги «дней в неделю» — догадка до калибровки (как веса перегруза); на первой неделе могут шуметь.
  Менять только константы.
- Нормы МР 2.3.1.0253-21 — таблицу надо перенести руками из PDF; ошибка в цифре ВДУП опаснее, чем
  отсутствие цифры. Проверка цифр — Влад по первоисточнику, в партии 1.
- `coach-food/SKILL.md` на лимите (28 Б запаса) — без выноса в `groups.md` тест упадёт.
- Записи до шага без групп: первые недели «мало данных» — `days_with_data` показывает это тренеру.
- Сопоставление курса из `med_course` (имя свободным текстом) с нутриентом делает модель — возможна
  ошибка; защита — тренер называет, что с чем сложил, и спрашивает «да» перед курсом (как в 8б).

## Открытые технические вопросы

1. Словарь групп (`FOOD_GROUPS`): рекомендую 12 ключей — fish (рыба и морепродукты), red_meat,
   poultry, eggs, dairy, legumes, nuts_seeds, greens (листовая зелень), vegetables, fruit_berries,
   whole_grains, organ_meat (печень). Больше — размытие, меньше — потеря сигналов. Решает Влад.
2. Хранение: таблица `food_group` (рекомендую, считается SQL-ом) или JSON-колонка в `food_log`.
3. Старые записи (с КБЖУ, без групп): не размечать задним числом (рекомендую — разнообразие с даты
   шага) или добавить `get_food_ungrouped` + проход тренера.
4. Пороги `GROUP_MIN_DAYS`: МР даёт нормы нутриентов, а не частоту групп — стартовые значения брать из
   общих диетологических рекомендаций (рыба 2 дня/нед, бобовые 2–3, зелень/овощи 5+, молочное 5+,
   орехи 3+, красное мясо — не «мало», а верхняя планка ≤ 3?). Утвердить как стартовые, калибровать
   по 3–4 неделям.
5. `groups` — необязательный параметр `save_food_nutrition` (рекомендую, один вызов в `coach-food`)
   или отдельный `save_food_groups`.
6. Где показывать сигналы: недельный обзор + по запросу (рекомендую) или ещё строкой в утренней
   сводке (`morning_snapshot` — лишний вес каждое утро).
7. Нормы по полу/возрасту: в `profile_log` нет пола и даты рождения — брать строку «мужчины 18–59»
   из МР константой (рекомендую) или добавить ключи профиля.
8. Нутриент у курса: модель по имени из `get_meds` (рекомендую, без миграции) или колонка `nutrient`
   в `med_course` (точнее, но правка CLI `coach med add`).
