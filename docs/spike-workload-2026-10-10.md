## Наблюдения → что меняется в каркасе

- **Повторы:** уникальных `eventIdentifier` — 19 на 178 событий (повторы делят id). Ключ `UNIQUE (source, uid, start_at)` из плана — верный и обязательный.
- **Доля типов:** all-day 2, повторяющихся 170, отделённых экземпляров (`isDetached`) 5, `status` none 160 / confirmed 18, `availability` busy 176. Участники есть у 16 событий (все accepted, организатор не Влад); declined и tentative в окне нет — правила подсчёта из плана оставляем, на реальных данных они почти не срабатывают.
- **Часовой пояс** задан у 176 из 178 — у двух (all-day) нет; all-day режем по местной дате.
- **Хвостовые пробелы** в названиях двух календарей — сравнение названий в конфиге делать по `strip()`.
- **Рабочих событий мало:** на рабочие календари — 19 из 178 в окне. Календарь работу показывает слабо; основной сигнал рабочей нагрузки — туду и груминг. Учесть при весах `total_load` (v2.2+v2.3).
- **Роль тренера:** текущий `coach.md` считает календарь «вне роли» — расширение роли в v2.1 (`coach-wellbeing.md`) обязательно.
- Вечер: не all-day событий, заканчивающихся после 18:30, — 8.

## Дополнение v2.6: запись (2026-10-11)

Скрипт `spikes/workload/calendar_write.py`, календарь коуча в iCloud, терминал Влада. Только синтетические события «ai-coach spike».

- **Доступ:** `authorizationStatus` 3 (полный) до и после, нового промпта TCC нет — запись из того же CLI без доп. разрешений. Swift-хелпер не нужен.
- **Календарь** ищется по точному названию (регистр важен), `allowsContentModifications` = True.
- **pyobjc:** `saveEvent_span_commit_error_` и `removeEvent_span_commit_error_` возвращают кортеж `(True, None)` — проверять первый элемент, второй — ошибка.
- **Чтение назад** по `eventIdentifier`: заголовок, календарь, заметка, начало, конец, таймзона (Asia/Tashkent), будильник −10 мин — совпадают.
- **Идентификаторы:** `eventIdentifier` = `<id календаря>:<calendarItemExternalIdentifier>`; после синка с iCloud (`--keep`, затем `--remove`) событие найдено по тому же `eventIdentifier` и удалено — id стабилен, хранить его как `calendar_uid` достаточно.
- **Повторяющееся** (ежедневное, 3 вхождения): у всех вхождений один `eventIdentifier`; удаление с `EKSpanFutureEvents` убирает все (0 осталось).
