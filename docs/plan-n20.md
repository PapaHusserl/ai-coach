## Суть

**Правило:** было `3 * i + 1 not in done_steps` (`src/ai_coach/load/plan_actual.py:28`, докстринг
«Упражнение i ↔ ACTIVE-подход с wktStepIndex = 3i + 1 (допущение, проверить на часах)») → станет
`3 * i not in done_steps` (при Р1 = (1)) либо сравнение по `exercise_name` (при Р1 = (2)).

**Причина (установлена, база только чтением, 2026-11-03).** Часы нумеруют шаги силовой без группы повторов:
у упражнения i рабочий подход — `wkt_step_index = 3i`, отдых — `3i + 1`. Код ждёт рабочий подход на `3i + 1`,
а там лежат только REST-подходы, поэтому все упражнения попадают в `missing_exercises`. Порядок загрузки и
формат кодов ни при чём: коды совпадают.

Живые данные (`strength_sets`, `set_type`, `wkt_step_index`):

| activity | дата | ACTIVE на шагах | REST на шагах | plan_actual |
|---|---|---|---|---|
| 24937687695 | 2026-11-02 | 0, 3, 6, 9, 12 | 1, 4, 7, 10, 13 | id 27, different, все 5 упражнений |
| 24854911109 | 2026-10-26 | 0, 3, 6, 9, 12 | 1, 4, 7, 10, 13 | id 21, different, все 5 |
| 24776210709 | 2026-10-19 | 0, 3, 6, 9, 12 | 1, 4, 7, 10, 13 | id 15, different, все 5 |

Тест закрепил то же неверное допущение: `tests/test_load_plan_actual.py:32-36` — «wktStepIndex = stepOrder - 1,
значит рабочие подходы — 1 и 4» (`BENCH_STEP = 1`, `ROW_STEP = 4`). Фикстура синка `tests/fixtures/garmin/
activity_sets.json` начинается с `wktStepIndex: 0` у первого подхода — ответ Garmin это и показывал.

**Поведение:** меняется — `get_plan_actual` и утренняя сводка тренера («факт вчера») для силовых: «done» вместо
ложного «different», `missing_exercises` только у реально пропущенных упражнений.
**Вне репо:** Влад после коммита запускает `uv run coach sync --days 16` (или больше) — пересчёт старых строк
plan_actual, при Р2 = (1).

**Справка (правило AGENTS.md):** функция тренера не меняется (ни команды, ни инструмента, ни шкалы) — правок
`.claude/agents/coach-help*` нет; `tests/test_skills_help.py` не затрагивается.

## Развилки

**Р1. По какому признаку сопоставлять упражнение и подход** (видно: какой статус и какие пропуски покажет тренер).
- (1) Индекс `3i` — минимальная правка, работает и для FIT-импорта, где `exercise_name` нет. Хрупко, если формат
  шагов `build_strength` изменится.
- (2) По `exercise_name` подхода против `exercise` плана, при пустом имени — по индексу `3i`. Не зависит от
  нумерации; лишняя ветка кода.
- Рекомендую (1): нумерация подтверждена тремя тренировками и фикстурой Garmin, `build_strength` не меняется
  в обозримых шагах. Выбор за Владом.

**Р2. Старые строки plan_actual** (видно: история за месяц в сводке тренера).
- (1) Влад запускает `coach sync --days 16` после коммита — синк пересчитывает plan_actual за охваченные дни.
- (2) Не пересчитывать: ложные «different» за 10-19, 10-26 уйдут из окна сводки сами (28-30 дней).
- Рекомендую (1): одна команда, тренер перестаёт видеть ложный флаг сразу. Выбор за Владом.

**Риски.**
- Подход, сделанный не по плану (часы без загруженной тренировки), — `wkt_step_index` пустой → все упражнения
  «пропущены», как и было; поведение прежнее, не регресс.
- Тренер уже сделал вывод по ложному флагу 2026-11-03 утром — память тренера не правится кодом; при желании
  Влад скажет тренеру сам.
