### «Много окон» — откуда (по коду)

- Источник правила — `coach.md:8`: любой выбор, «да/нет» перед записью и любая оценка 1–5 — окном. Отсюда 191 окно за
  14 дней и до 57 за вечер (замер выше). Чек-ин (`coach-evening/SKILL.md:15`) уже собирает 4 вопроса в одно окно — это
  образец, остальные скилы и свободный разговор так не делают.
- В этом шаге: (а) запись срыва — ноль окон (без силы и без подтверждения); (б) Р6 = 1 — окна чек-ина не растут;
  (в) Р10 = 1 — правка текста `coach.md:8` (Правило п. 2). Глубже (разбор каждого скила) — пункт BACKLOG «меньше окон
  в скилах» (номер — по RULES, заводит оркестратор), не в этом шаге.

### «Не синхронизирован с календарем» — что видно в коде и данных

Как устроено: календарь читается только командой `coach sync` (`sync/workload_sync.py:113 read_calendar`, окно −N…+14
дней, `AHEAD_DAYS` `agenda/service.py:30`); фонового запуска нет (launchd-агента coach нет); MCP к календарю не ходит
(инструкция сервера). Тренер пишет только черновики, в календарь их кладёт Влад `coach event write`.

Найденные расхождения (живая база, только счётчики):

1. **Перенос в Календаре не доходит до тренера.** `own_events` (`workload_sync.py:~56`) кладёт время из календаря в
   `calendar_events`, но `coach_events.start_at` не трогает; `get_agenda`/`agenda_rows` (`agenda/service.py:205`)
   показывает старое время. Сейчас 4 записанных события, у которых время в календаре ≠ время у тренера (сдвиги 30 мин –
   4 ч, одно — сегодня). Плюс `busy_spans` (`agenda/slots.py:32`) берёт и `calendar_events`, и `agenda_rows` — перенесённое
   событие занимает два слота (старый и новый) при планировании дня.
2. **Снимок устаревает между sync.** План дня (`create_day_plan`, `agenda/day_plan.py:272`) и агенда строятся по базе
   на момент последнего `coach sync`; что Влад добавил/сдвинул после — тренер не видит до следующего sync.
3. **Ручные события в календаре коуча игнорируются** (`own_events`: «чужие пропускаются», в итоге sync только счётчик).
4. **Черновики не в календаре.** План дня существует у тренера, пока Влад не выполнил `coach event write`; сейчас
   просроченных черновиков 0, но на сегодня/вперёд — 8 (focus 2, meal 3, task 2, rest 1).

Решено (Р9 = 1, 2026-11-03): пункт BACKLOG «синхронизация с календарём» с симптомами 1–4, отдельный шаг после Н19;
при заведении шага — спросить Влада, какой симптом он видит; п. 1 — первый кандидат (баг, видно в данных).

## Развилки и риски

Все развилки решены Владом (Решения 2026-11-02, 2026-11-03); ниже — итог, без отброшенных вариантов.

- **Р1.** Свободный текст эмоций, без силы и списка; команда `coach slip "текст"`.
- **Р2.** `--at HH:MM` — срыв в созвоне отмечается позже.
- **Р3.** CLI + фраза «срыв: …» в открытой сессии `тренер`.
- **Р5.** `awake_h` + `stress_garmin` (±15 мин, данные уже в базе) — партия 2.
- **Р6.** Вечернего вопроса о срывах нет; окна чек-ина не растут.
- **Р7.** Мешают окна и календарь → Р9, Р10.
- **Р8.** Выводы: по просьбе + абзац в недельном обзоре + одна строка в итоге вечернего чек-ина (шаг 4 скила; без
  записей — молчание). В snapshot срывы не идут.
- **Р9.** Календарь — пункт BACKLOG, отдельный шаг после Н19.
- **Р10.** Правка `coach.md:8` (Правило п. 2) + пункт BACKLOG «меньше окон в скилах».

Риски:

- Данные к окну v2.9 (2026-11-10): отметок будет ≤ 8 дней — в калибровку срывы войдут только взглядом, не признаком;
  признак «срывов в день» для `load/` — после Н6/Н8 с месяцем данных.
- Лимиты текстов: `wellbeing.md` запас 938 Б — раздел может не влезть (выход — файл `slips.md`, вторая allow-строка
  Владу); `coach.md` запас 830 Б; `coach-evening/SKILL.md` запас 330 Б — самый тесный (allowed-tools + фраза итога).
  Прибавки — ожидание, не проверено; кабан меряет `wc -c` после правки.
- Строка в вечернем итоге (Р8 = 3) — ежедневное сообщение о срывах; если Влад почувствует её помехой — снять строку из
  шага 4 скила (текст), без кода. Чек-ин делает лишний вызов `get_slip_log` — отдельный, snapshot не меняется.
- `settings.json` правит Влад — до правки тест на allow красный и фраза в сессии будет спрашивать разрешение; кабан пишет
  об этом в хэнд-бэке, не правит сам.
- Стресс Garmin за сегодня — до момента последнего `coach sync`; отметка днём, sync вечером — поле появится после sync
  (поведение данных, не ошибка). Значения −1/−2 (нет замера) исключаются — проверить на живой базе при партии 2.
- Усталость от ввода: отметка добровольная, напоминаний нет; если за неделю < 3 отметок — не чинить напоминаниями, а
  спросить Влада (бэклог).
- Текст эмоций — личные данные, свободный текст «без фильтров»: хранится только в локальной базе; в документы, тесты,
  pipeline и хэнд-бэки не попадает; в репо — только выдуманные фикстуры. Через `get_slip_log` текст уходит в Claude —
  как уже уходят чек-ин и еда; Владу сказать об этом в справке одной фразой.
- Длинные тексты: `get_slip_log` упирается в общий потолок 20000 символов (`cap`) — при многословных записях за месяц
  `truncated=true` раньше 60 строк; тренер просит период короче (поведение сервера, не ошибка).
- Выводы тренера по свободному тексту — интерпретация; без диагнозов (как `coach-week.md` п. 3), формулировку держит
  текст скила.
- Правка `coach.md:8` меняет поведение во всех скилах сразу — проверка руками Влада после партии 1.
