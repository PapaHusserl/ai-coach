# П5. Веб-пульт: туду (CRUD, в календарь) и чужие события календаря (BACKLOG 71, 72)

## Суть

План архитектора 2026-11-11 (заготовка Н28 дополнена; контур вне msa, режим «встроить»).

**Задача:** пульт ведёт туду (список, добавить, править, состояния) и ставит задачу туду в календарь пунктом плана
(BACKLOG 71); чужие события календаря открываются окном и правятся — время, название, описание, удаление (BACKLOG 72,
Р1). Режим — встроить: сервер `web/*.py` + таблицы `POST_ROUTES`/`GET_VIEWS` (`server.py:78,127`), статика парами
`*-model.js` (чистые, тесты `node --test`) и `*-pane.js` (DOM, руками), как П3–П4.

**Правило** (меняется задачей, первый пункт аппрува):
- было `locked = (row) => row.repeat != null || row.source === "meeting"` (`scale-model.js:78`) → станет
  `row.source === "item" ? row.repeat != null : !row.editable` (Р8 = 1, Р11 = 1 — решено; `editable` отдаёт сервер, см. Файлы);
- было `hasWindow`: `row.source === "item" && …` (`pult-model.js:81`) → станет `row.source === "meeting" || (…как было…)`
  (Р7 = 1 — решено);
- было докстринг `calendar_write.py:3-4` «Пишет и снимает только в календаре коуча … чужие календари и чужие события
  недостижимы» → станет «`CalendarWriter` — только календарь коуча; чужие события правит `ForeignWriter`
  (`agenda/calendar_edit.py`) по паре (uid, start_at), только это вхождение»; `calendar.md:7` «Чужие календари тренер не
  меняет» → «тренер не меняет; вы правите их в пульте (`pult-todo.md`)»;
- было `_meetings` (`web/day.py:77`) берёт все `list_calendar_events` → станет без строк, чей `uid` есть в
  `coach_events.calendar_uid` (регресс области, см. «Что уже есть»).

**Поведение:** меняется — карточка «Туду» под «План дня» на вкладке «План» (Р2 = 2), только открытые пункты (Р3 = 2),
окно у серой строки встречи и перетаскивание серого блока (Р7 = 1, Р11 = 1), список встреч без дублей пунктов тренера.
План дня тренера, `coach todo`, `coach event *`, MCP — без изменений. Все развилки Р2–Р15 решены Владом 2026-11-11
(«Решения»); новые из решений — Р16, Р17 («Развилки и риски»).

**Вне репо:** `.claude/settings.json` — Р13 = 1: Влад добавляет `Bash(cat .claude/agents/coach-help/pult-todo.md)`
(правило AGENTS.md). Доступ к Календарю у процесса `coach web` уже есть: тот же, что у синка из пульта (`syncer.py`) и
`CalendarWriter` в `apply_event`.

## Что уже есть (разведка)

Измерено на HEAD aaae830 2026-11-11: grep, `wc -c`, `wc -l`, живая база read-only (`?mode=ro`), EventKit только чтение
(скрипт в scratchpad; названия календарей и событий не печатались).

- **Чужие события в пульте.** `day_view` → `_meetings` (`web/day.py:77-95`) читает `calendar_events` за `day-1..day`
  (`store/workload.py:73 list_calendar_events`), фильтр `_counted` (не cancelled/declined), `_clip` по полуночи; наружу
  белый список `id, start_at, end_at, all_day, title, calendar` (тест `test_web_day.py:539`). Таблицу наполняет только
  `coach sync` / `coach sync --calendar` (`sync/workload_sync.py:217 sync_workload`, окно `today-days..today+14`,
  `AHEAD_DAYS = 14` `workload/service.py:18`; `replace_calendar_window` `store/workload.py:46` — ключ `(source, uid,
  start_at)`). Живого чтения календаря в пульте нет; «обновить» в шапке — полный синк (П4). Поля строки
  (`calendar_eventkit.py:75 _row`): `uid` = `eventIdentifier`, `calendar`, `title`, `start_at/end_at`, `all_day`, `status`,
  `my_status` (участник-я: accepted/declined/…; None — без участников), `raw_json.{recurring, detached, time_zone}`.
  **Описания (notes) в снимке нет** — ни колонки (`migrations/0015_workload.sql:5-21`), ни в `raw_json`.
- **Как отличить чужое от тренерского.** `stored_events` (`workload_sync.py:39`) пропускает календарь коуча (`category ==
  "coach"`), `own_events` (`:58`) добавляет в `calendar_events` **записанные тренером** события с категорией (для
  нагрузки) — с `calendar` = календарь коуча и `uid` = `coach_events.calendar_uid`. Чужие события внутри календаря коуча
  (`foreign`, BACKLOG 55) в базу не попадают — П5 их не видит и 55 не закрывает. Признак тренерского в `calendar_events`:
  `uid` ∈ `coach_events.calendar_uid` (`store/agenda.py:65 find_by_uid`).
- **Регресс области (измерено):** П1 считал, что календарь коуча в `calendar_events` не попадает (`docs/plan-p1.md:46-48`,
  «ожидание по коду»); на живой базе за 14 дней вперёд — 4 строки тренера (`written`: 3 task, 1 rest), и `day_view` того
  дня отдаёт их в `meetings` — 4 серых дубля блоков тренера на шкале и в списке. Правка `_meetings` — в партию 3 (правило 9).
- **Снимок за 14 дней вперёд (живая база):** 18 чужих событий, 3 календаря, категории personal 15 / work 2 / rest 1;
  `recurring` 11 (61 %), `detached` 2, all_day 0, с участниками 2, с заметками 0 (EventKit). Календарей у системы 20,
  из них 5 без права записи (`allowsContentModifications()` False — подписки/праздники).
- **EventKit и повторы (измерено):** `store.eventWithIdentifier_(uid)` у повторяющегося возвращает **первое вхождение
  серии** (строка 2026-11-11T10:00 → объект 2026-11-02T10:00), так работает `CalendarWriter.move/remove`
  (`calendar_write.py:94,116`) — для чужих повторов не годится. Вхождение находится предикатом дня
  (`predicateForEventsWithStartDate_endDate_calendars_`, как `CalendarReader._events` `:119`) и совпадением
  `(eventIdentifier, startDate) == (uid, start_at)`: 18 из 18 строк снимка найдены. Запись одного вхождения —
  `saveEvent_span_commit_error_(item, EKSpanThisEvent, …)` (в Календаре вхождение станет «отделённым»), серии —
  `EKSpanFutureEvents`; удаление — `removeEvent_span_commit_error_` с тем же span (`:122`). Проверка на запись не
  делалась (ожидание по документации Apple, стенд — Влад).
- **Писатель.** `CalendarWriter` (`calendar_write.py:22`): `_open` → ровно один календарь коуча с правом записи;

## API и модель (внутреннее)

- `GET /api/todo` → `{items: [{id, title, note, state}]}` — только `todo`/`doing` (Р3 = 2), `date` игнорируется. `POST
  /api/todo` — `{op: "add", title, note}` → `{id}`; `{op: "edit", id, title?, note?}` → `{}`; `{op: "move", id, state}` →
  `{}` (`state` ∈ `doing | todo | done | dropped`; чужое → 400); ошибки `TodoError` текстом 400 (как CLI: «Нельзя todo ->
  todo (можно: …)», «пустое название», «Нет задачи #N»).

  записи — живьём из EventKit, Р10 = 1; EventKit недоступен → `note: null`, `editable: false`, `reason` = текст ошибки). `POST /api/meeting` — `{action: "update", id,

  («Встречи нет — обнови синк»), 400 — текст `CalendarError`/проверок. Строка базы правится после календаря (как
