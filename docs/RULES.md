# Правила для агентов: docs/ и гигиена репо

Версия 4 — 2026-10-26. Файл одинаковый во всех проектах; кладёт и обновляет его дашборд
(`mix dashboard.scaffold --rules <проект>`). Правила конкретного проекта — в AGENTS.md, не здесь.
Процесс и роли — family.md; при расхождении прав family.md. Общие практики — COMMON.md дашборда.

## Зачем

Состояние проекта живёт в трёх файлах `docs/`, у каждого одна роль. Закрытое уходит в `docs/done/`,
подробности шага — в его документ. Тексту без роли в этих файлах не место; временное в репо не кладём.

## docs/ROADMAP.md — карта: куда идём

- Ведёт архитектор. Только он встраивает пункты беклога в роадмап и переранжирует их. Оркестратор (основная
  сессия) ROADMAP не пишет и не правит — даже по решениям пользователя: записывает их в документ шага или
  `NOTES.md` и зовёт архитектора; роадмап выдаёт архитектор.
- Норма строки и блоков — в COMMON.md дашборда, «Норма ROADMAP». Маркеры: ✅ сделан, ▶ стартовал, ⛔ отменён,
  ⏸ заблокирован; без маркера — не стартовал.
- Пройденное, текущее и будущее — вместе с git это история шагов. Шаг закрыт → ✅ в его строке.
- Текст пункта беклога не дублируется — только `(BACKLOG N)`.

## docs/BACKLOG.md — ещё не сделанное

- Пункт: `## N. Название`, строки `status:` / `priority:` / `updated:`, затем тело.
- Статусы: idea, research, planned, started, done, dropped.
- Нумерация: следующий номер = наибольший из `## N.` в BACKLOG.md и числовых префиксов файлов
  в `docs/done/` + 1. Номера не переиспользуются никогда.
- Пополняет любой — только добавлением пункта в конец. Ход работы, отчёты, решения сюда не пишут.
- Пункт со статусом done или dropped переносит в `docs/done/` тот, кто закрыл шаг, в том же коммите,
  что ✅ в ROADMAP. В беклоге такие пункты — только проездом; дашборд показывает «к переносу: M».

## docs/done/ — карточки закрытых пунктов

- Имя: `NNN-nazvanie-latinicey.md` — номер пункта в три цифры, транслит названия строчными, дефисы
  (дашборд подсказывает имя у закрытого пункта). Дашборд читает только номер из имени и шапку файла.
- Содержимое: первая строка `# N. Название`; затем `status: done` или `status: dropped`,
  `priority:`, `updated: <дата закрытия>`; затем исходное тело пункта без правок;
  затем `## Закрыто` — шаг, дата, ссылка на документ шага (или причина снятия, если шага нет).
- Больше ничего: решения, стоимость и проблемы живут в документе шага.

## Документ шага — docs/plan-<шаг>.md

- Один файл на шаг по постоянному адресу, не переезжает. Разделы: суть, «Решения» пользователя,
  шаги/партии, тесты, риски; по ходу — «Правки по ревью»; при закрытии — «Итог»: закрытые пункты
  беклога, стоимость (пишет кабан-тесть), проблемы.
- Документ шага — это план и его приложения (например, макеты в `docs/mockups/`). Отчёты агентов,
  чек-листы прогонов, черновики — не документы шага: им место в чате или scratchpad, не в репо.
- Шаг без пункта беклога тоже имеет документ; пункт, закрытый несколькими шагами, ссылается на каждый.
- Имена остальных документов `docs/` — по таблице в COMMON.md дашборда, «Документы проекта».

## docs/handoff.md — закладка для новой сессии

- Перезаписывается, не дописывается. Около 50 строк, не больше 80.
- Разделы: «Где мы» (3–5 строк) · «Следующие 3 шага» (из ROADMAP) · «Открытые вопросы» · «Ссылки»
  (документ текущего шага, последний коммит, AGENTS.md).
- Обновляет оркестратор после каждого шага, затем очищает контекст; новая сессия начинает с него.
- Чего в handoff нет: истории шагов (git + ROADMAP), решений (документ шага), описания процесса (AGENTS.md).

## Решения

- По шагу — в документе шага, раздел «Решения». Процессные («как работаем») — в AGENTS.md.
- Вне шага и не процессные — датированной записью в `NOTES.md`.
- Архитектурные (состав и порядок шагов, стек, модули, хранилище) принимает только архитектор. Оркестратор
  их не принимает, даже «по решениям пользователя»: фиксирует решение пользователя в документе шага или
  `NOTES.md` и передаёт архитектору.
- В трёх файлах и карточках — только ссылки на них.

## Гигиена репозитория и агентов

- В git — только нужное проекту: код, тесты, конфиги, документы по этим правилам. Отчёты агентов,
  чек-листы прогонов, черновики, логи, дампы, выгрузки — в репо не лежат и не коммитятся.
- Временное — в scratchpad сессии (каталог даёт среда); агент убирает за собой. Что порождают сборка
  и инструменты (зависимости, кэши, `.DS_Store`, дампы) — в `.gitignore`, не в «неотслеживаемых».
- Корень проекта — скелет (README, AGENTS.md, CLAUDE.md, NOTES.md, `.dashboard.json`, `.gitignore`) и
  файлы инструментария (mix.exs, package.json…); остальное — по папкам. Старые копии (`*.OLD.md`, `*.bak`)
  не хранят: история — в git.
- Коммит — законченная работа: партия или шаг целиком (код, тесты, документы, ROADMAP/BACKLOG/done/ разом),
  пополнение беклога, перебор ROADMAP. Сообщение — что сделано, по-русски, со ссылкой на шаг и
  `(BACKLOG N)`, если шаг закрывает пункт. После коммита `git status` чист. Точный формат сообщения
  и работа с ветками — в AGENTS.md проекта.
- Агент не оставляет фоновых процессов, занятых портов и «второго сервера для просмотра»: запустил —
  остановил; если что-то должно жить дальше — записать в handoff.
- Новые зависимости — только с явного согласия пользователя; lock-файл — в git.
- Секретов в репо нет: ключи, токены, пароли — в окружении или вне репо (`~/.config/…`), в конфиге только
  путь. Не попадают они и в документы и логи. Секрет оказался в git — сразу сказать пользователю.

## Проверка

Дашборд (`~/projects/dashboard`) читает три файла и `docs/done/`. Если этот файл отличается от
шаблона дашборда — в деталях проекта предупреждение «правила устарели».
