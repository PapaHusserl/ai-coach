# Версия 2: веллбиинг-коуч — план (черновик на утверждение)

Статус: **proposed**, ред. 2 (2026-10-10). Реализация — только после утверждения Владом.

## Источник и цель

Идея — карточка дашборда `~/projects/dashboard/ideas/wellbeing-coach.md` («Велбинг-коуч», priority high): коуч смотрит на нагрузку целиком — работа, нагрузка вне тренировок, хобби, отдых, общая нагрузка как их сумма. В документах ai-coach про v2 ничего не было.

**Главная проблема Влада — подступающее выгорание.** Цель v2 — регулировать объём и нагрузку на организм: видеть общую нагрузку (тренировки + работа, её много, + хобби) против восстановления и вовремя её снижать.

## Решения Влада (2026-10-10, через супервизора)

1. Опоры: сон, стресс, настроение (ментальное), привычки, **загруженность** — работа, хобби, баланс работы и отдыха. Ядро — календарь и общая нагрузка, нужны инсайты.
2. Один агент: расширяем `тренер`, отдельного не делаем.
3. Ритм: утренний разбор + вечерний чек-ин.
4. Ментальное: только оценки настроения и стресса и практики; дневника и КПТ нет.

Ответы на вопросы карточки дашборда: расширение ai-coach (новые модули); коуч советует, предупреждает о перегрузе и перестраивает план тренировок черновиками (как в v1); источник данных о работе — календарь (какой — открытый вопрос 1).

## Что меняется относительно v1

| | v1 | v2 |
|---|---|---|
| Нагрузка | Только тренировки: TSS → CTL/ATL | **Общая нагрузка за день/неделю** = тренировки + работа (часы и плотность встреч из календаря, переработки, вечера/выходные) + хобби; тренд против восстановления |
| Восстановление | Сон, HRV, BB, readiness, самочувствие 1–5 | То же + вечерние оценки настроения и стресса |
| Риск выгорания | Нет | Сигнал перегруза: высокая общая нагрузка несколько дней подряд + падение восстановления/настроения; пороги — константы модуля, как в шаге 10 |
| Реакция | Пересчёт плана при плохом восстановлении | + снизить объём тренировок черновиком, предложить отдых/«пустой» вечер, указать перегруженные дни календаря на неделю вперёд |
| Ритм | Утренний разбор | + вечерний чек-ин: настроение, стресс, работа/хобби/отдых за день (короткие оценки) |
| Стресс | Метрики Garmin | + короткие практики (дыхание, пауза), подбор по стрессу/BB |
| Привычки | Нет | Небольшой трекер (состав — вопрос 2) |
| Недельный обзор | План недели | + обзор нагрузки и баланса работы/отдыха, инсайты |
| Тренировки, еда, спортпит, курсы | — | Без изменений |

Принципы v1 остаются: данные в SQLite через CLI/MCP, логика в промптах; MCP только читает и пишет черновики; на часы отправляет только Влад; календарь только читаем.

## Этапы

Каждый этап — по циклу «Общее для шагов 2–8» в `plan.md`: груминг, план папы-кабана, TDD, ревью, аудит.

1. **v2.0 — спайк календаря:** получить события за 30 дней из выбранного источника (вопрос 1), понять поля, отличить работу, хобби и личное (календари, цвета, ключевые слова). Отчёт — без личных данных.
2. **v2.1 — загруженность:** импорт событий в базу (`calendar_events`, синк как `coach sync`), классификация работа/хобби/отдых, метрики дня: рабочие часы, встречи, вечера/выходные с работой. MCP `get_workload`, раздел в snapshot.
3. **v2.2 — вечерний чек-ин:** оценки настроения и стресса (расширить `wellbeing_log`), ручная отметка работы/хобби/отдыха там, где календаря нет; скил `/coach-evening`, вход из `тренер` вечером.
4. **v2.3 — общая нагрузка и сигнал выгорания:** модуль `load/` + общая нагрузка, пороги перегруза, реакция в агенте (снижение плана черновиками, разгрузка), прогноз по календарю на неделю.
5. **v2.4 — практики и привычки:** справочник практик стресса/сна (как рецепты), трекер привычек.
6. **v2.5 — недельный обзор и агент:** инсайты (нагрузка ↔ сон ↔ настроение), роль коуча в `coach.md` с выносом частей в файлы (лимит размера промпта ~15 КБ).

## Открытые вопросы к Владу

1. **Календарь:** какой источник — Google Calendar (коннектор claude.ai есть, но для `coach sync` нужен свой доступ), Apple Calendar на маке, рабочий Exchange/Outlook, экспорт .ics? Один или несколько (рабочий + личный)? Kaiten для работы — нужно или хватит календаря?
2. **Привычки:** какие трекать в первом релизе (вода, шаги, экран вечером, «без работы после 20:00»…) — или отложить v2.4?
3. **Данные:** события календаря (названия встреч) хранить в локальной базе — ок, или только агрегаты (часы, количество)?
4. **Первый релиз:** v2.0–v2.3 (календарь + вечер + сигнал выгорания), остальное потом — согласен?

Модель и деньги — по умолчанию как в v1 (Sonnet), вечерний чек-ин проверит кабан-тесть на v2.0.
