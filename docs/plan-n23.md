Дата: 2026-11-07. Ведёт архитектор. BACKLOG 46 (симптомы 1–2), 38, 4. Вход — docs/plan-roadmap-r2.md «Решения»
(Р1 = 2, Р2 = 1, Р3 = 2, Влад 2026-11-07), docs/plan-n19.md «Не синхронизирован с календарем».

## Суть

**Правило (первым пунктом аппрува):**
1. Перенос в Календаре: было `own_events` кладёт время из календаря только в `calendar_events`, `coach_events.start_at`
   не трогает (`sync/workload_sync.py:58`) → станет: у записанного неповторяющегося события расхождение
   `start_at/end_at` с календарём переписывает `coach_events.start_at, end_at, date` в той же транзакции sync.
2. Повтор: было `REPEATS = ("daily",)` (`agenda/service.py:28`) и `CHECK (repeat = 'daily' AND kind = 'checkin')`
   (миграция 0023) → станет `REPEATS = ("daily", "weekly", "biweekly")`, CHECK `repeat IN (...) AND kind = 'checkin'`.
3. Перенос через тренера: было — команды нет (`cli/agenda.py`: list/write/remove/cancel) → станет
   `coach event move <id> <начало>` и MCP-инструмент переноса (форма — Р1).
4. Свежесть: было — календарь читает только полный `coach sync` (Garmin + нагрузка, `cli/main.py:135`) → станет
   быстрый путь только календаря (форма — Р2).

**Поведение:** меняется — `get_agenda`, `coach event list`, план дня показывают время из Календаря; в Календаре
появляются еженедельные/двухнедельные напоминания; новые команда и MCP-инструмент.
**Вне ai-coach:** Влад — строка allow для быстрого sync, если Р2 ≠ (1) (`coach sync:*` уже есть,
`.claude/settings.json:8`); `coach event move` в allow не ставится (пишет в Календарь, как `event write` — его тоже
нет в allow). Окно данных v2.9: `load/*` не трогается — `grep -rn calendar src/ai_coach/load` даёт одно
совпадение `calendar_date` (Garmin, не календарь); `calendar_events` не меняется по смыслу.

## Развилки

Видимое Владу — решает он.

- **Р1. Форма MCP-переноса.** (1) Новый инструмент `move_draft_event(event_id, start_at)`: черновик двигает сам
  (черновики MCP уже пишет), у записанного в базу не пишет и возвращает готовую команду
  `coach event move <id> <время>` — Влад выполняет; без миграции. (2) `create_draft_event(..., replaces=<id>)`:
  новый черновик со ссылкой, `coach event write` пишет новый и снимает старый — нужна колонка `replaces_id`
  (миграция) и ветка в `write_event`; две вещи в одной команде. (3) Колонка «предложенное время» у записанного
  + `coach event move <id>` без времени применяет предложение — миграция, новое состояние события.
  Рекомендую (1): ни миграции, ни нового статуса, правило «MCP пишет только черновики» не нарушено.
  Без ОВ-2/3: ~25 строк (оценка по плану), теряем «одна команда write применяет всё».
- **Р2. Быстрый путь календаря.** (1) `coach sync --calendar` — только нагрузка, без Garmin (флаг; `coach sync:*`
  в allow уже покрывает). (2) Отдельная команда `coach calendar sync` — нужна строка allow у Влада. (3) MCP читает
  календарь сам при `get_agenda`/`create_day_plan` — EventKit в процессе MCP (доступ к календарю у процесса сервера),
  ломает инструкцию «к календарю MCP не ходит». Рекомендую (1). Видимое: имя флага, когда тренер его вызывает
  (перед планом дня и переносом — предлагаю; альтернатива — только по просьбе Влада).
- **Р3. `coach event move` — что задаёт Влад.** (1) Только новое начало, длительность сохраняется. (2) Начало и
  `--end`/`--minutes`. Рекомендую (1) + необязательный `--minutes` позже, если понадобится (сейчас не делать).
- **Р4. Конфликт повторов.** Сейчас: два активных повтора на одно время суток запрещены. (1) Конфликт — то же время
  суток и пересечение дней (daily ↔ любое; weekly/biweekly — тот же день недели). (2) Как сейчас — любое совпадение
  времени суток, независимо от периода (WHO-5 в 20:00 по воскресеньям не встанет рядом с ежедневным чек-ином в
  20:00). Рекомендую (1). Видимое: какие напоминания тренер может поставить.
- **Р5. `move` у повторяющегося.** (1) Запретить с текстом «повторяющееся — снять и поставить заново» (`event remove`
  + черновик). (2) Двигать всю серию (`EKSpanFutureEvents`, как `remove`). (3) Только одно вхождение — EventKit
  отсоединяет его, в базе у серии один uid — расходится с моделью. Рекомендую (1): повторяющиеся — только чек-ины,
  переносятся редко; (2) — если Влад хочет менять время напоминания одной командой.
- **Р6. Перенос в Календаре на связанной тренировке.** Событие с `workout_id` сдвинуто в Календаре на другой день —
  тренировка в Garmin остаётся на старом. (1) Только событие + замечание в итоге sync «тренировка N перенесена в
  календаре, на часах — старая дата». (2) Только событие, молча. Рекомендую (1). Перенос тренировки на часах — не Н23.
- **Р7. Что ещё тянуть из Календаря.** (1) Только время (start/end/date). (2) И название. Рекомендую (1) —
  симптом 1 про время; переименование — без данных о частоте.
