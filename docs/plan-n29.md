## Суть

**Задача:** тренер приносит решения о будущем (утвердить тренировки, принять фазу, слот, тяжёлые дела, отложенное с
вечера) утром, вечером сам предлагает только отдых и снятие набранного; отложенное словами попадает в очередь и утром
всплывает; время решения и исполнение записываются — замер (BACKLOG 69, наблюдение Влада 2026-11-10; Р1 = 2).

**Правило (первым пунктом аппрува):**

1. Новое: времени суток у предложений тренера сегодня нет — `coach.md` п. 2, 8а, 9, 9в (`:20, :28, :30, :33`)
   срабатывают в любой час. Станет: по полю сводки `day_part` (новое) — утром (до 12:00) решения на будущее одним блоком
   после сводки, днём сам не приносит (Р3), вечером (с 19:00 до 04:00) новых обязательств не предлагает. Текст — новый
   файл `.claude/agents/coach-decisions.md`, указатель в `coach.md` (п. 9ж, новый) и в `coach-evening/SKILL.md`.

   `tests/test_mcp_snapshot.py:92`) → станет `snapshot["day_part"] = day_part(tools.now()) if date ==
   tools.today().isoformat() else None`, значения `"morning" | "day" | "evening"` (Р2: 12:00 и 19:00).

   (миграция 0032), команды `coach decide …`, ключ сводки `decisions_pending`, инструмент MCP `get_decisions`.
   Отложенное вечером и днём тренер кладёт в очередь, утром приносит вместе с тем, что уже лежит в базе.
   По Р11 = «всё подряд» в очереди лежат и черновики тренировок, и предложенные фазы: один журнал решений,
   у каждой строки вид (`kind`) и ссылка на объект (`ref_id`) — «Следствия Р11».
4. Было: принять или отклонить фазу нечем — `accept_phase` и `reject_phase` (`goals/service.py:247, :256`) зовут
   только тесты, команды CLI нет (`grep -rn 'accept\|reject' src/ai_coach/cli/` — пусто), хотя `coach.md:20` велит
   «напомни принять или отклонить». Станет (Р17 = 1): `coach decide done <id>` на пункте фазы зовёт

5. Было `coach-week.md:9` п. 3 без строки о решениях → станет: в п. 3 добавлена строка замера по `get_decisions`
   (Р15 = 2): цифры за недели обзора и вывод тренера, когда в части дня набралось не меньше 10 решений с исходом (Р19 = 3,

**Поведение:** меняется — (а) утром тренер после сводки сам называет накопившиеся решения списком с загрузкой целевого
дня: из очереди (сказанное словами, черновики тренировок, предложенные фазы — Р11) и из сводки то, у чего строки в

## Модель (внутреннее)

Таблица `decision_log` (миграция 0032), по образцу `slip_log` — текст как есть, строки не удаляются:

- `id INTEGER PRIMARY KEY`; `text TEXT NOT NULL CHECK (length(trim(text)) > 0)`;
- `kind TEXT NOT NULL DEFAULT 'text' CHECK (kind IN ('text', 'workout', 'phase'))`; `ref_id INTEGER` — id строки
  `planned_workouts` или `phases`; `CHECK ((kind = 'text') = (ref_id IS NULL))`; уникальный индекс по
  `(kind, ref_id)` при `ref_id IS NOT NULL` — на объект один пункт (Р11 = 2);
- `target_date TEXT` — день, которого касается решение (`NULL` — без даты): у тренировки — её `date`, у фазы —
  `start_date`;
- `created_at TEXT NOT NULL` — когда отложено (у черновика и фазы — когда созданы);
- `status TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'yes', 'no', 'dropped'))`; `decided_at TEXT`;
- Р13 = 1: `result TEXT CHECK (result IS NULL OR (result IN ('kept', 'missed') AND status = 'yes'))`,
  `result_at TEXT` — пишутся только у `kind = 'text'` (Р18 = 1);
- индекс по `status`.

Перенос в миграции: открытые пункты на черновики с `date >= date('now', 'localtime')` и на фазы `proposed`
(`INSERT … SELECT`, `created_at` — из строки объекта); на живой базе сегодня это 0 строк («Разведка»).

Переходы: `open` → `yes` | `no` | `dropped` (`close_decision`, только из `open`, иначе `False`); `yes` → `result`
(`set_result`, один раз). Часть дня не хранится: считается `day_part` от `created_at` и `decided_at`.

Кто кладёт и кто закрывает (Р11 = 2, Р12 = 1; Р16 = 1, Р17 = 1):

| Вид | Кладёт | «да» | «нет» | «снято» |
|---|---|---|---|---|
| `text` | тренер: `coach decide add` | `decide done <id>` | `decide done <id> --no` | `decide done <id> --drop` |
| `workout` | код в `create_draft_workout` | `coach approve <id тренировки>` | `coach cancel` черновика | `cancel_draft_workout` (тренер) |
| `phase` | код в `propose_phase` | `decide done <id>` → `accept_phase` | `decide done <id> --no` → `reject_phase` | нет |

Команды: `coach decide add "<текст>" [--for YYYY-MM-DD]` (только `text`); `coach decide list [--all]` (без `--all` —
открытые; колонки по Р14: id, целевой день, текст, когда отложено; у `workout` и `phase` в тексте — вид и id объекта);
`coach decide done <id> [--no | --drop]` (без флага — «да»; оба флага — ошибка; не `open` — ошибка «уже решено»; пункт
`workout` — ошибка с подсказкой «`coach approve <id>` или `coach cancel <id>`»; пункт `phase` с `--drop` — ошибка
«принять или отклонить»; при ошибке `accept_phase` — rollback, пункт остаётся открытым); `coach decide result <id>
[--missed]` (без флага — исполнено; не `yes`, результат уже есть или пункт не `text` — ошибка). Правки и удаления нет:
ошибся — `--drop` и новая запись.

Сводка: `decisions_pending.rows` — `id, kind, ref_id, text, target_date, created_at` открытых; порядок (Р14 = 1) —
ближайший `target_date`, без даты в конце, при равенстве старший `created_at`; пункт с `target_date < date` остаётся в
списке (тренер помечает «срок прошёл»). `decisions_to_check.rows` — `id, text, target_date, decided_at` у
`kind = 'text'`, `status = 'yes'`, `result IS NULL`, `target_date < date` (без `target_date` исполнение не
спрашивается; `workout` и `phase` не входят — Р18 = 1).

MCP `get_decisions(date_from, date_to)`: строки с `created_at` или `decided_at` в периоде (≤ 92 дней, `tools.period`),
поля таблицы плюс `created_part`, `decided_part`; у `kind = 'workout'` поле `result` считается при чтении из
`plan_actual` по `planned_id = ref_id` (`done` → `kept`; `skipped`, `different` → `missed`; строки нет — `null`), в
таблицу не пишется (Р18 = 1); у `phase` `result` всегда `null`. `stats` — по строкам с `decided_at` в периоде, по
`decided_part` (`morning`, `day`, `evening`): `yes`, `no`, `dropped`, `kept`, `missed`. Выводов в коде нет: вывод по Р19 = 3 делает
тренер по тексту `coach-week.md`, сравнивая `kept` + `missed` части дня с порогом 10 (Р20 = 1); константы
и поля порога в коде нет.

   тренер команд не добавляет, «лишних вызовов вечером» из текста Р11 нет; расхождение «черновик утверждён, пункт
