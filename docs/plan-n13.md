## Суть

Влад: «не думать, когда работать, отдыхать, готовить еду и тренироваться» (BACKLOG 26). Занятые часы — из
календарей через `coach sync`, внезапные задачи — из туду с оценкой времени, тренировка — из плана; тренер кладёт
черновики, в календарь пишет `coach event write` после «да».

Что есть сейчас (измерено на HEAD, база `~/.local/share/ai-coach/coach.db`):

- Занятые часы уже в базе с началом и концом: `calendar_events` (`store/workload.py:replace_calendar_window`,
  поля `start_at`/`end_at`/`title`/`category`/`status`/`my_status`), окно sync `today−days … today+14`
  (`sync/workload_sync.py:sync_workload`, `AHEAD_DAYS = 14`). Вперёд сейчас 11 событий на 8 дней (2026-11-02…11-13):
  personal 8, hobby 2, work 1 (all-day). Ответ r1 «хватает ли хранимых start/end» — хватает, календарь при
  планировании читать не нужно; свежесть — на момент последнего `coach sync` (тренер делает его при каждом старте,
  `coach.md:17`).
- События тренера: `coach_events` (миграция 0019), статусы draft → written → removed / cancelled; черновик —
  `agenda/service.py:create_draft` → `validate_draft` (kind из `KINDS`, −30…+14 дней, ≤ 24 ч, категория: у `task`
  обязательна, у `rest`/`sleep` по умолчанию `rest`, у остальных запрещена → в нагрузку не идут). Запись в календарь —
  только CLI `cli/agenda.py:event_write` (не в allow, двойное «да» — решение Влада 2026-10-11, docs/plan-v2.md:95 (2)).
  В базе 59 записанных событий (task 39, training 10, checkin 4, rest 2, practice 1) — механизм живой.
- Чтение событий тренера: `agenda_rows` (draft/written + активные повторяющиеся), MCP `get_agenda`, в snapshot
  `agenda` −1…+7 (`mcp_server/snapshot.py:176`, компактные поля, `part()` ≤ 20 строк / 4 000 символов).
- Тренировка плана: `planned_workouts` (`store/plans.py:list_planned_workouts`) — дата без времени; длительность —
  `sport_nutrition.py:workout_duration_min` из `estimated_duration_secs`. Слот тренировки сейчас ставит тренер по

- Нагрузка и сигналы: `load/overload.py:hours` — ручные > экран > календарь; `work_evening_hours` — только

- Образцы: смена CHECK в SQLite — пересоздание таблицы (`store/migrations/0009_pantry_expiry.sql`); инструмент

Что строим: детерминированный раскладчик дня в коде — свободные окна дня минус занятое (календари + события тренера),
по правилам v1 блоки задач, фокуса, еды, отдыха и тренировки; MCP-инструмент создаёт их черновиками за один вызов;
тренер по триггеру показывает раскладку, после «да» — `coach event write <id…>`; туду — чтением активных пунктов
командой, минуты спрашивает тренер.

**Правило:** было `KINDS = ("training", "practice", "rest", "sleep", "checkin", "task")` (`agenda/service.py:26`) и тот же
CHECK в `coach_events.kind` (0019) → станет `KINDS = (…, "focus", "meal")` (при Р2 = (1); миграция 0023 пересоздаёт
таблицу по образцу 0009); категории у `focus`/`meal` нет (`_category` → None, как у training/practice/checkin) — блоки
плана в нагрузку не входят. Новое правило раскладки (`agenda/day_plan.py`, новый): `free = [day_start, day_end) −
busy`, где `busy` = события `calendar_events` дня (не отменённые, не отклонённые, не all-day — те же `_counted`, что в
нагрузке) ∪ события тренера дня (draft/written, кроме `checkin`); рамка дня — по дню недели (Р5, числа Влада): будни
`10:00 … 00:00`, сб/вс `11:00 … 00:00` (`00:00` — следующая полночь); блоки кладутся в окна ≥ `MIN_SLOT` в порядке:
задачи Влада → тренировка (если задано время) → еда и отдых (якорные: завтрак 11:00 будни / 12:00 сб/вс, перекус
15 мин в 15:30 будни / 16:00 сб/вс, отдых 30 мин сразу после него, ужин 19:00) → фокус; ничего не пересекается, окна < `MIN_SLOT` остаются
пустыми для задач и фокуса; после `EVENING_FROM` (19:00) и в сб/вс фокус-блоков нет; вечер после ужина свободен (Р7 =
(1)): задачи туда попадают только когда днём не влезли, тренировка — по `training_at`.
**Поведение:** меняется — новый триггер «спланируй день/завтра», «план дня» → раскладка и список черновиков с id,
после «да» `coach event write`; при Р3 = (2) вечерний чек-ин после ритуала закрытия дня предлагает «разложить завтра?»;
при Р4 = (2) новая команда `coach todo` (чтение). Сводка, snapshot, нагрузка, недельный обзор — без правок: черновики
плана видны в `agenda` snapshot как любые черновики.
**Вне репо:** календарь коуча в iCloud (есть, `[coach] calendar`); поле оценки времени в `todo.json` — владелец скил
`whats-up` (`~/.claude/skills/whats-up/todo.py`), в этом шаге не трогаем — пункт для skill-intake, если Влад захочет
хранить минуты в туду (Р4). Новых зависимостей нет. После партии 1 — перезапуск MCP-сервера (новый инструмент).

   полночь, иначе `day_end` в тот же день и должен быть позже `day_start`.
