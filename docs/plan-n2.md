## Суть

PVT (psychomotor vigilance test): на экране в случайные моменты появляется стимул, человек жмёт клавишу как можно
быстрее; метрики — время реакции и «провалы» (lapses). Самый чувствительный маркер недосыпа; 3-минутная версия PVT-B
(Basner, Mollicone, Dinges 2011, https://pmc.ncbi.nlm.nih.gov/articles/PMC3197786): интервал между стимулами 1–4 с,
порог провала 355 мс вместо 500 мс у 10-минутного теста. Это объективная пара к субъективным оценкам `coach focus`
(Н1) и `readiness` Garmin; сравнивать их будут Н9 (профиль дня) и v2.9/Н6 — здесь только сбор.

## Развилки и риски

Принято Владом 2026-10-31 («Решения»), в редакции, которая действует:

- **Р1 = 1. Форма теста.** Терминал, PVT-B: 3 минуты; пауза перед стимулом случайная 1–4 с; стимул — яркая строка
  `●●●  ЖМИ  ●●●` (в месте курсора, экран не очищается); ответ — пробел (Enter тоже); после ответа 0,5 с показывается RT
  («312 мс»); фальстарт — нажатие до стимула или RT < 100 мс («Рано»); провал — RT > 355 мс; нет ответа 10 с — проба
  записывается как 10 000 мс (провал), тест продолжается; Esc или Ctrl-C — «Прервано, не записано»; ограничений по
  времени суток нет, запусков в день — сколько угодно (анализ Н9 возьмёт первый за день). Отклонённые: страница в
  браузере с ручной записью (кандидат беклога, если захочется с телефона); классический 5-минутный.
- **Р2 = 2. Метрики.** Медиана RT, среднее RT, медленные 10 % (средний RT самых медленных ceil(n × 0,1) проб),
  скорость (среднее 1/RT, 1/с), провалы, фальстарты, число проб — на экране, в `coach log pvt` и в `get_pvt_log`; сырой
  список RT — в базе (`rts`), наружу не отдаётся. Основание выбора Влада — метрики PVT-B (Basner 2011: mean 1/RT и
  slowest 10 % — самые чувствительные к недосыпу).
- **Р3 = 1. Режим наблюдения.** Только `get_pvt_log` по просьбе и `coach log pvt`; сводка, snapshot, отклонения не
  трогаются (NOTES 2026-10-31; как Р7 Н1, plan-n1.md «Решения» 2026-10-31). Реакция — v2.9/Н6/Н9 по ряду.
- **Р4 = 2. Напоминание — событие в календаре.** Ежедневный `checkin` в календаре коуча через существующий поток
  (черновик тренера → «да» → `coach event write`), без кода; ставит Влад словами после партии («Проверка руками»).
  Отклонённые: без напоминания; режим `тренер тест` в `bin/trener`.

Новая развилка (следствие Р4 = 2, видимое — время и текст события):

- **Р5. Время и вид напоминания.** Рекомендую: ежедневно, включая выходные (`repeat` только `daily`, как у «Фокус
  1–5?»), 09:30, заголовок «Реакция 3 мин», 5 минут, `alarm_min=0`, заметка — `uv run coach pvt` без личного текста.
  Почему 09:30: по живой базе Н1 утренняя запись `feel` идёт в 09–13 (сессия `тренер`, plan-n1.md «Суть»), тест нужен
  до сессии и после пробуждения, пока оценка «свежести» не замылена работой; PVT — маркер недосыпа, чем ближе к подъёму,
  тем чище. Альтернативы: (2) 10:00 или другое время словами Влада — меняется без кода (черновик → write; поменять =
  `event remove` + новый); (3) без заметки (чище календарь, команду помнить). Разблокирует «Проверку руками», не код;

## Умолчания (внутреннее)

1. `pvt_log`: `id INTEGER PK, date TEXT NOT NULL, started_at TEXT NOT NULL, duration_s INTEGER NOT NULL, trials INTEGER
   NOT NULL CHECK (trials >= 0), false_starts INTEGER NOT NULL CHECK (>= 0), lapses INTEGER NOT NULL CHECK (>= 0),
   mean_rt_ms INTEGER, median_rt_ms INTEGER, slow10_ms INTEGER, speed REAL, rts TEXT NOT NULL` (JSON-список, `null` —
   фальстарт); индекс `pvt_log_date`. Порог провала и доля медленных в строке не хранятся — константы `pvt.py`; сменятся
   — новая колонка тогда. Имя `slow10_ms` фиксирует долю 10 % в названии — так читается в MCP без справки.
2. `date` — `wellbeing_day(started_at)` как у `coach focus`; `started_at` — момент старта теста (первая клавиша), `now()`
   из `cli/journal.py`; записи только добавляются, правки/удаления нет (как `focus_log`).
3. Модуль `ai_coach/pvt.py` без typer и sqlite; `cli/pvt.py` — только склейка (TTY-проверка, запуск, запись, вывод).
   Часы — `time.perf_counter` (не `datetime`, его подменяет `fake_clock`); случайность — `random.Random()` по умолчанию,
   в тестах `Random(0)`.
4. `wait_key(timeout_s, fd=None)`: `select.select([fd], [], [], timeout)` → `os.read(fd, 1)`; `fd` по умолчанию
   `sys.stdin.fileno()`, явный — для pty-теста; `timeout_s=None` — без предела (стартовая клавиша в `cli/pvt.py`);
   пробел и `\n`/`\r` — ответ; `\x1b` и `\x03` — `KeyboardInterrupt`; прочие байты — тоже ответ (Р1 = 1 — «пробел
   (Enter тоже)», лишние клавиши не штрафуем). Стимул после фальстарта — новая пауза, фальстарт считается пробой.
   Пауза `FEEDBACK_S` после результата и `tcflush` — в `terminal_show`, не в `run_test` (ядро теста без `sleep`,
   часы внедряемые — тесты `run_test` идут мгновенно).
5. `summarize`: `mean_rt_ms`, `median_rt_ms`, `slow10_ms` — целые (`round`), по пробам с числом (включая
   `NO_RESPONSE_MS` — «нет ответа» тянет медленные вверх, это и есть сигнал), без фальстартов; медленные — `ceil(round(n ×
   SLOW_SHARE, 6))` наибольших RT (`round(…, 6)` — страховка от двоичного `0.1`; измерено: для n < 400 без неё результат
   тот же), не меньше одной; `speed` — среднее `1000 / rt`, `round(…, 2)`; `lapses` — `rt > LAPSE_MS`; нет ни одной
   пробы с RT — `None` в четырёх полях. Строку итога даёт `format_summary(row)` — одна для `coach pvt` и `coach log pvt`.
6. `get_pvt_log(date_from, date_to)` — как `get_focus_log`: `period` ≤ 92 дней, `cap(newest=True)`, поля строки без
   `rts` (список ~55 чисел на строку × 60 строк — лишние ~15 КБ в ответе), `slow10_ms` и `speed` — есть; описание
   инструмента в `server.py` называет единицы (мс, 1/с); в snapshot не входит (Р3 = 1).
7. `coach pvt` — не в allow `.claude/settings.json` и не в списке Bash `coach.md:10`; `coach log pvt` работает через
   существующее `log`.
8. Вывод `log pvt`: `id  started_at  медиана NNN мс, среднее NNN, медленные 10 % NNN, скорость N,NN/с, провалы N,
   фальстарты N (проб K)`; при `None` (одни фальстарты) — «нет проб с ответом, фальстарты N (проб K)». Итог `coach pvt` —
   та же строка (`format_summary`) без `id` и времени, с хвостом « - записано.».
9. Тексты экрана теста — русские, без личных данных; в репо и доках — никаких результатов Влада (репо публичное).
