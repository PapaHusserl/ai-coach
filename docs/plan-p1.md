# П1. Веб-пульт: сервер и главная (BACKLOG 49)

## Суть

Первый шаг пульта (разрез — docs/plan-roadmap-r2.md «Разрез пульта», Р4 = 3 и Р6 = 1 — решения Влада 2026-11-07,
там же «Решения»). П1 только читает базу: локальный сервер командой `coach web`, главная — план дня: события
тренера (`coach_events`, живые draft/written, как `agenda_rows`) и встречи других календарей (`calendar_events`)
серым, без окон (Р4 = 2). Текущий пункт подсвечен, прогресс-бар «прошло / осталось». Доступ с телефона в домашней
сети (Р2 = 2). Окон пункта, записи и правки плана нет — это П2–П4. `load/*` не трогается — окно данных v2.9 цело.

**Правило:** новое — «пульт показывает день из двух источников: события тренера — только
`agenda_rows(conn, day, day)` (как `coach event list` / MCP `get_agenda`); встречи — только
`list_calendar_events(conn, day, day)` с фильтром `_counted(e)` (как `slots.busy_spans`); пульт в базу не пишет».
**Поведение:** не меняется у существующих команд; новое — команда `coach web` и страница в браузере, в т. ч. с
телефона в домашней сети.
**Вне репо:** нет обязательного. Строку allow `Bash(uv run coach web:*)` в `.claude/settings.json` добавляет Влад,
только если захочет, чтобы тренер сам поднимал пульт (рекомендую не добавлять: долгоживущий процесс в сессии
агента — против RULES «не оставлять фоновых процессов»). При Р2 = 2 macOS при первом запуске спросит «разрешить
входящие подключения для python» — нажимает Влад.

## Решения

Влад, 2026-11-07, окнами (кто решил: Влад):
- Р1 = 1 — сервер на стандартной библиотеке (`http.server`), без новых зависимостей.

- Р3 = 1 — бар по времени от начала первого пункта до конца последнего.
- Р4 = 2 — события тренера + встречи других календарей серым, без окон; не по рекомендации.

- Р6 = 1 — без защиты в сети; не по рекомендации (риск назван в окне: любой в Wi-Fi видит план и встречи).
- Р7 = 1 — у встречи название, как в Календаре; не по рекомендации.

- Р9 = 1 — встречи на весь день строкой сверху.
- Р10 = 1 — при пересечении встречи и пункта тренера текущими подсвечены оба.

## Модель данных `day_view` (внутреннее)

Вход: `conn`, `day: date`, `now: datetime` (в тестах — подмена, как `today` в `validate_draft`). Выход — dict:
- `date`, `now`;
- `items` — из `agenda_rows`, по `start_at`; поля id, kind, title, start_at, end_at, all_day, status, note, repeat
  (`repeat` — для раскладки повторов по дням; правка по партии 1, 2026-11-07);
- `meetings` — из `list_calendar_events(conn, day-1, day)`, `_counted`, пересекающие сутки `day` (`_clip`);
  поля id (внутренний, для подсветки), start_at, end_at, all_day, `title` (Р7 = 1), `calendar`. `raw_json`, `uid`,
  `my_status` в JSON не идут никогда;
- `current` — список `[{"source": "item"|"meeting", "id": …}]` всех пунктов тренера и встреч, где
  `start_at <= now < end_at`, по `start_at`; пусто — `[]` (Р8 = 2, Р10 = 1);
- `elapsed_min`, `left_min` — по Р3 = 1, рамка — от самого раннего начала до самого позднего конца среди пунктов
  тренера (включая повторы своего дня) и встреч не на весь день (Р8 = 2; повторы — решение Влада, «Правки по
  ревью», последний абзац).
`all_day` (тренера и встречи, Р9 = 1 — строкой сверху) — в список, вне шкалы и прогресса. Повторы
(`active_repeats` с ранней датой, у чек-ина время суток переносится на `day`) — только в свой день, не на весь
день входят в рамку бара и в `current`. Пересечение — подсвечены все идущие (Р10 = 1; при Р10 = 1 это же и для двух
пунктов тренера — прежнее «текущий первый по `start_at`» снято).

## Тесты

- Пустой день → `items=[]`, `meetings=[]`, `current=[]`, прошло 0, осталось 0. Ожидание, не проверено.
- Три пункта 09:00–10:00, 10:00–11:00, 12:00–13:00, now 10:30 → current — [второй]; прошло/осталось 90/150 мин
  (Р3 = 1: от начала первого до конца последнего с паузами).
- now 11:30 (в паузе) → current `[]`, бар не прыгает назад.
- now ровно 10:00 → current — [второй], первый не входит (граница `start <= now < end`).
- cancelled/removed тренера не видны (через `agenda_rows`); draft виден с пометкой «черновик».
- Встречи: `status='cancelled'` и `my_status='declined'` не видны; встреча 23:00 накануне–01:00 видна с 00:00;
  встреча целиком вчера — не видна; в JSON нет `raw_json`, `uid`, `my_status` (проверка по ключам); `title` есть
  (Р7 = 1).
- Р8 = 2: пункт тренера 09:00–10:00 и встреча 14:00–15:00, now 14:30 → current `[{"source": "meeting", …}]`; рамка
  09:00–15:00, прошло/осталось 330/30 мин. Встреча 08:00–08:30 раньше пунктов тренера → рамка начинается с 08:00.
- Р9 = 1: встреча на весь день — в `meetings` с `all_day`, не текущая, рамку не двигает.
- Р10 = 1: встреча 10:00–11:00 и тренировка 10:30–11:30, now 10:45 → current — оба, по `start_at` (встреча,
  затем тренировка); now 11:00 → только тренировка. Два пункта тренера внахлёст → оба.
- JS: все элементы из `current` получают класс подсветки (тест в `pult.test.mjs`).
- Повторяющийся чек-ин, заведённый неделю назад, weekly — виден только в свой день недели; daily — каждый день.
  Ожидание: `agenda_rows` отдаёт повторы без фильтра по дню недели — `day_view` фильтрует сам (новое).
- Сервер: `GET /api/day?date=2026-11-07` → 200 JSON; `date=мусор` → 400 с текстом; `/static/../x` → 404;
  неизвестный путь → 404; POST, PUT, DELETE, PATCH, OPTIONS → 405; HEAD → 501 без тела («Правки по ревью»). Сервер в тесте — на порту 0, база — `tmp_path`
  (как `conftest.py`).
- `coach web` без `--host` слушает `0.0.0.0` (Р2 = 2, Р6 = 1); запрос без всяких параметров доступа → 200.
- `coach web --port N` занятый порт → понятная ошибка через `fail`, не трейсбек.
- JS: `node --test tests/web/` — формат HH:MM, ширина бара 0..100 %, «сб, 7 ноября».
- mutmut: `ai_coach.web.day.*` — TESTS `tests/test_web_day.py`; `ai_coach.web.server.*` — `tests/test_web_server.py`
  (`MOD` в Makefile берёт изменённые модули сам).
- Руками: `uv run coach web` → на Mac сегодняшний план тот же, что `coach event list`; встречи — те же, что в
  Календаре, серым, идущая сейчас встреча подсвечена; с телефона в той же Wi-Fi по напечатанному адресу — та же
  страница, без ключа.

## Развилки

Р1–Р10 решены (см. «Решения», Влад, 2026-11-07, этот файл). Открытых развилок нет.

Риски:
- **Доступ без пароля в сети (Р2 = 2, Р6 = 1 — решение Влада).** Любой в той же Wi-Fi (гости, открытая сеть,
  кафе) видит план дня и названия встреч. HTTP без TLS. Сервер только читает, POST нет — записать в базу через
  пульт нельзя; но П2–П4 добавят запись — там защиту придётся решать заново (развилка в П2). DNS-rebinding (сайт
  в браузере Влада читает пульт по LAN-адресу) — открыт (ожидание, не проверено); проверка заголовка `Host` —
  предложение, не в плане (~5 строк; видимого не меняет, но отвечает Владу 403 при входе по чужому имени).
- **Приватность названий встреч (Р4 = 2, Р7 = 1 — решение Влада).** `calendar_events.title` — рабочие встречи;
  сегодня наружу из базы они идут только MCP на один день по явному запросу. Пульт отдаёт их в сеть без ключа.
  В JSON — белый список полей, `raw_json` (сырой ответ календаря) не уходит никогда (тест по ключам).
- **Бар от встреч (Р8 = 2).** Ранняя встреча (08:00) или поздняя (21:00) растягивает рамку — бар «прошло»
  покажет день длиннее плана тренера. Это следствие решения, не баг; Справка пишет одной строкой.
- **Свежесть встреч.** `calendar_events` обновляет только `coach sync`; пульт показывает то, что было на последний
  sync. Время последнего sync в шапке — предложение, не в плане (видимое; добавить — с решением Влада).
- **Связь с BACKLOG 55.** Ручные события календаря коуча на пульте не видны (их нет ни в одной таблице) — Влад
  может принять это за баг пульта. Справка пишет это одной строкой; сам пункт — П4.
- Пульт открыт, а `coach sync` или тренер пишут в ту же SQLite — читатель на отдельном соединении на запрос,
  без долгих транзакций; блокировок не ждём (ожидание, не проверено). `coach sync` заменяет окно
  `calendar_events` — запрос посреди замены увидит старое или новое целиком, если замена в одной транзакции
  (проверить в партии 1, `store/workload.py:53–70`).
- Повторы: `agenda_rows` не раскладывает weekly/biweekly по дням — пульт покажет weekly-чек-ин не в тот день,
  если не фильтровать (заложено в `day_view`). Если тот же баг есть у `coach event list` — это регресс области,
  проверить в партии 1 и при подтверждении чинить там же (правило 9), отдельной строкой «Правки». Проверено —
  см. «Правки по ревью», партия 1: не регресс, `agenda_rows` не меняется.
- Фоновый процесс: `coach web` живёт до Ctrl-C; агентам не запускать (см. «Вне репо»).
- Брандмауэр macOS при `0.0.0.0` спросит разрешение — без «разрешить» телефон не откроет (см. «Вне репо»).
