## Суть

У события типа `checkin` появляется опросник — имя готового набора вопросов. Его называет тренер при создании события
(MCP `create_draft_event`, новое поле `survey`, без него — отказ) или Влад в форме нового пункта пульта. Пульт
открывает под пунктом анкету этого опросника, а не всегда анкету вечера. Опросников пять: `evening` (анкета вечера),
`feel` (самочувствие), `focus` (оценка фокуса), `none` (без анкеты: «Сделал / Пропустил») и `who5` (WHO-5, партия 3).

**Правило** (первый пункт аппрува): было — форму и «красное» пункта задаёт только тип события:
`ALLOWED["checkin"] = ("checkin",)` (`web/marks.py:29`), `"checkin": not evening` (`web/marks.py:208`),
`TABS.checkin = ["checkin"]` (`web/static/marks-model.js:14`) → станет — у `checkin` их задаёт опросник события:
`SURVEY_MARKS[row["survey"] or "evening"]` на сервере и `SURVEY_TABS[survey ?? "evening"]` в пульте; «красное» —
по отметке своего опросника. У остальных типов (`task`, `focus`, `practice`, `rest`, `training`, `meal`) правило прежнее.
Второе правило (партия 2, решение Р3 = 2): было `PULT_KINDS = ("task", "focus", "rest", "meal")` (`web/plan.py:22`,
П4 Р5 = 1) → станет `("task", "focus", "rest", "meal", "checkin")`.
**Поведение:** меняется — окно чек-ина в пульте, «красное» у чек-ина, `create_draft_event` (новое обязательное у
чек-ина поле), `get_agenda` (новое поле в строке), `coach event list` (хвост «опросник: …»), форма нового пункта
пульта (пятый вид), запись WHO-5 из пульта (партия 3). Не меняется: запись анкеты вечера (`web/marks.py:97 _checkin`),
`evening_done` (`store/journal.py:227`), `load/*`, скил `coach-evening`, записи журнала, уже созданные чек-ины
(Р7 = 1). Правило окна v2.9 (ROADMAP «Сейчас») цело: константы и формулы не трогаются, записи не переписываются;
пороги WHO-5 v2.9 не калибрует (ROADMAP, строка Н12).
**Вне репо:** нет. Новых команд CLI нет — строк allow не нужно. После правки MCP-схемы (партии 1 и 3) — перезапустить
MCP-сервер, тренеру нужна новая сессия (handoff «Что важно помнить»).
