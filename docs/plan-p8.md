## Суть

Три пункта беклога — два независимых куска в одном окне еды пульта.

- **Списание (BACKLOG 67, 62).** «Съел вариант N» пишет запись еды с КБЖУ и группами, но запись не помнит свой
  вариант (в `food_log` нет `offer_id`), а продукты состава из кладовой не уходят: кладовую правят только `coach pantry
  use` (тренер после «да», `coach-food/SKILL.md:14`) и вкладка «Еда». Шаг добавляет `food_log.offer_id` и списание
  строк состава, которые нашлись в кладовой.
- **Добавки к приёму (BACKLOG 60).** Журнал приёма (`intake_log`) принимает только добавки (`supplement`); курсы
  (`med_course`) отметить нечем — ни командой, ни в пульте. Шаг расширяет журнал на курсы и ставит в окно еды блок
  «Добавки к приёму» (прототип BACKLOG 49, `:390` по docs/plan-p3.md:31) с отметкой «принял».

**Правило** (первый пункт аппрува), по «Решениям»: Р1 = 1, Р2 = 1, Р13 = 2:

1. Было (`web/food.py:33-36`): `add_food(conn, {"event_id": …, "logged_at": …, "text": text} | values)` → станет:
   `add_food(conn, {…} | values | {"offer_id": offer["id"]})`, затем `use_offer(conn, offer["items"], food_id, now)`
   (новая): строка состава списывается, если `normalize(what)` равно названию продукта с остатком, `qty` читается как
   «N г | мл | шт» и единица та же; остальные строки не списываются.
2. Было (`coach-food/SKILL.md:14`): «Только после „да“: `uv run coach pantry use …`» — единственный путь списания еды
   → станет: в чате — как было; клик «Съел вариант N» в пульте — сам согласие на списание, второго вопроса нет.
3. Было (`store/migrations/0014_intake_log.sql:7`): `kind TEXT NOT NULL CHECK (kind IN ('supplement'))` → станет:
   `CHECK (kind IN ('supplement', 'med'))` (пересборка таблицы, как 0023).
4. Было (`store/intake.py:15`): `insert(conn, INTAKE, {"kind": SUPPLEMENT, **values})` → станет: `{"kind": kind,
   **values}`, `kind` — `supplement` или `med`; `list_intake` соединяет с таблицей своего вида.
5. Было: приём курса отметить нечем (ни команды, ни экрана) → станет: приём курса пишет и снимает только пульт
   (`POST /api/intake`, новый); команд `coach med take|log|untake` нет, тренер приём курса не пишет (Р13 = 2) и
   отсылает в пульт (Р15 = 1). Было (`coach-nutrition.md:3`): «Приём добавок: журнал - `get_supplement_log` … отметку
   снимает пользователь сам (`untake`).» в тексте роли, про курсы правила нет → станет: в роли указатель на
   `coach-nutrition/intake.md` (новый), там прежний абзац без правок и правило про курсы — раздел «Вынос».
6. Было (`store/intake.py:30-31`): `delete_intake(conn, log_id, deleted_at)` снимает любую строку журнала → станет:
   снимает только строку своего вида — `coach supplement untake N` приём курса не трогает.
7. Не меняется: запись «своё» текстом, остаток дня, красное у еды (П3 Р2 = 1), `create_meal_offers` и его схема,
   `record` и правила кладовой (`pantry/service.py:63`), `coach supplement take|log|untake` и их ответы (журнал
   `coach supplement log` — по-прежнему только добавки), набор команд `coach med`, `load/*`.

**Поведение:** меняется — где: (а) окно еды: после «Съел вариант N» остатки кладовой уменьшаются, под «Записано ✓»
строка о списанном (Р3); (б) окно еды: блок «Добавки к приёму» с отметками (Р7–Р12, Р16–Р18); (в) тренер: `taken`

«принял <курс>» в чате и утром после названия непринятого тренер не пишет приём и отвечает «Курс отмечается в
пульте: окно приёма пищи, блок „Добавки к приёму“.» (Р15 = 1); (г) `coach log food`, `get_food`, запись «своё», команды `coach
supplement` и `coach med` — не меняются.

**Вне репо:** строк allow `Bash(uv run coach med …)` шаг не требует (Р13 = 2: новых команд нет). До полного прогона
партии 2 Влад добавляет в `.claude/settings.json`, в `permissions.allow`, после строки 84 (`…/variety.md`), одну
строку (Р15 = 1; кабану классификатор менять свои настройки запрещает):
`"Bash(cat .claude/agents/coach-nutrition/intake.md)",` — без неё тренер не прочтёт вынесенный файл, а тест
`test_allow_can_read_intake_file` (новый) красный. После партии 2 — `/mcp` reconnect (схема `get_meds`, `get_supplement_log`). Начало шага — `uv run coach report list` (AGENTS.md),
