## Суть

У события тренера есть заметка (`coach_events.note`); у напоминаний тренер кладёт в неё команду или подсказку
(`uv run coach pvt`, `uv run coach who5`, «скажи тренеру: итоги недели» — `.claude/agents/coach-agenda.md:15–17`).
Сервер пульта заметку уже отдаёт, пульт её не рисует. Шаг показывает заметку в плане дня. Где и в каком виде —
развилки Р1–Р4, решает Влад.

**Правило** (первый пункт аппрува): было — `rowNode` (`web/static/pult.js:87`) кладёт в строку пункта
`item.append(head)`, затем бар идущего пункта и окно; `row.note` не читается нигде в статике пункта тренера
(`grep -c note pult.js` — 0, `marks.js` — 0, `pult-model.js` — 0) → станет (при Р1 = 1) — после `head`:
`if (note) item.append(el("div", "note", note))`, где `note = noteText(row)` (новая, `pult-model.js`).
При Р1 = 2 правило меняется в другом месте: `paneNode` / `mountMarks` (`web/static/marks.js:37, :256`).
**Поведение:** меняется — план дня в пульте: у пункта тренера с заметкой появляется её текст. Не меняется: сервер
(`/api/day`), база, MCP, CLI, тексты тренера, окно чужой встречи (там описание уже есть — `meeting-pane.js:56`),
шкала дня. Правило окна v2.9 (ROADMAP «Сейчас») цело: `load/*` и записи не трогаются.
**Вне репо:** нет. Новых команд CLI нет — строк allow не нужно. Схема MCP не меняется — перезапуск MCP-сервера и
новая сессия тренера не нужны.

**Р4. У каких пунктов.**
(1) У всех пунктов тренера с заметкой: черновики, прошедшие, идущие, будущие; при листании дней — тоже.
(2) Только у идущих и будущих; у прошедших скрыта.
(3) Только у чек-инов (напоминаний).
Рекомендую (1): прошедшее красное напоминание — как раз случай, когда команда нужна; у задач и отдыха заметки тоже
