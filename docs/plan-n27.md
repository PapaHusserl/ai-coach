# Н27. Тест `coach event list` не зависит от сегодняшней даты (BACKLOG 70)

Контур: вне msa; режим: встроить. Автор плана — папа-кабан, 2026-11-10.

## Суть

`tests/test_cli_agenda.py::test_list_shows_events_with_ids_and_statuses` (строка 200) красный с 2026-11-10:
`seed()` кладёт событие из `coach_event()` (`tests/workload_fakes.py:112`, дата 2026-10-10), а `coach event list`
без `--from/--to` берёт окно от реального `date.today()` (`src/ai_coach/cli/agenda.py:77`): [сегодня − 30,
сегодня + 14] = [2026-10-11, 2026-11-24] на 2026-11-10. Событие выпало из окна, команда печатает «Событий нет.»
(проверено: `uv run pytest tests/test_cli_agenda.py -k list` → `AssertionError: assert 'Первая синтетика' in
'Событий нет.\n'`).

Класс дефекта: фиксированная дата в данных теста + реальное «сегодня» в коде. Чиним тест, не код.

**Правило:** было — тест читает окно от реального `date.today()` (`cli/agenda.py:77`), данные на 2026-10-10 →
станет — «сегодня» теста зафиксировано `freeze(monkeypatch, "2026-10-10 12:00:00")` из `tests/fake_clock.py`
(при Р1 = 1). Правил кода не меняет.

**Поведение:** не меняется (тест-only). **Вне репо:** нет.

## Развилки

**Р1 — как зафиксировать «сегодня» в тесте** (внутреннее: пользователю не видно; рекомендацию можно принять без
обсуждения).

1. `freeze(monkeypatch, "2026-10-10 12:00:00")` из `tests/fake_clock.py` — как в 9 файлах тестов. Данные
   `coach_event()` не трогаем, путь «окно по умолчанию с непустым выводом» остаётся покрытым. Проба зелёная.
   **Рекомендую.**
2. `run("list", "--from", "2026-10-01", "--to", "2026-10-20")` — как сосед на строке 219. Минус: путь окна по
   умолчанию с непустым выводом остаётся без теста (226 и 237 проверяют только код выхода).
3. Даты относительно реального сегодня (`**OLD_TIME`, строки 270–273) — согласованно с тестами `move`, но смешивает
   динамические даты с фиксированной `created_at` фикстуры; константы объявлены ниже теста — переносить.
4. Параметр `today` у `event_list` — трогает `src/` ради теста; отказ.

**Р2 — соседи того же класса (226, 237)**: (1) не трогать — суть тестов не зависит от строк в выводе;
**рекомендую**. (2) добавить `freeze` и в 226 для симметрии — +2 строки, пользы нет.

**Риски:** `freeze` поверх ленивых импортов не действует (`fake_clock.py:3`) — в `cli/agenda.py` импорты на уровне
модуля, риск не реализуется. Общий `freeze` на весь файл (autouse) недопустим: `SOON`/`NEW_DAY` считаются от
реального сегодня, а `move_draft` проверяет окно от `date.today()` → упали бы тесты `move`. Поэтому `freeze` —
только внутри теста 200.
