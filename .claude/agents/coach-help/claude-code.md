# Решающие события в Claude Code

Зачем: число реплик и вопросов-решений в Claude Code по дням - прокси «числа решений» (наблюдение, к цели «чувствовать себя комфортно»). В нагрузку, сигналы и план дня эти числа не входят.

## Что считается - `coach sync`, `coach claude`

- Что это: тренер читает локальные транскрипты Claude Code (`~/.claude/projects`) и за каждый день 04:00-04:00 считает пять чисел: `claude_prompts` - реплики пользователя; `claude_prompts_evening` - из них с 19:00 до 04:00; `claude_decisions` - вопросы-решения (каждый вопрос в окне вопросов - одно решение); `claude_repos` - проекты (каталоги), в которых были реплики; `claude_switches` - переключения между проектами у соседних реплик.
- Что не считается: субагенты, служебные строки и прерывания, SDK-агенты, сессии самого тренера, коммиты, время работы агентов. Тексты сообщений в базу не попадают; хранятся числа и короткие имена проектов.
- Как запустить: `coach sync` читает этот источник вместе с туду и грумингом; отдельно - `uv run coach claude [--days N]` (по умолчанию 1 день; до 04:00 - вчера). Первый раз - `uv run coach claude --days 29`, чтобы забрать всё, что ещё лежит в транскриптах. Подробности опций: `coach claude --help`.
- Что получу: строку «Claude <день>: реплик N (вечером K), решений M, репо R, переключений S»; имена проектов в строку не выводятся. Нет каталога транскриптов - «транскриптов нет». Тренер видит те же числа через `get_workload` (поля `claude_prompts`, `claude_prompts_evening`, `claude_decisions`, `claude_repos`, `claude_switches`; null - не считалось); имена проектов дня (`claude_repos_names`: проект и число реплик) - только `get_workload` с `events=true` на один день; в утренней сводке - ключ `claude` за 7 дней, без имён.
- Оговорки: Claude Code хранит транскрипты 30 дней, дальше история есть только в базе тренера; считается только этот компьютер. Разметка не нужна.
